## 这支片的选择

- 1920×1080、24 fps、26 镜；浅色手绘、中文旁白。实现为 Pillow 过程绘制与 FFmpeg，不能称为 Manim 成片；后来引入的 Skill Manim 缓存测试不是它的制作证据。
- 跟着同一台笔记本、无线接口和地址面板走；有线仅作对照。
- 特定前提：IPv4、无有效租约、远端 DNS 解析器、初始邻居缓存未命中、HTTPS/TCP。这些条件解释本片顺序，不表示每次联网都要完整重走同样步骤。
- 先完成一次访问，再明确回看同一 DNS 查询；断开/恢复后另起历史工作站演示 RARP。不同叙事时间和设备不会混成一次流程。

## 可复用的五种方法

| 方法 | 本片的可见例子 | 新题目怎样迁移 |
|---|---|---|
| 保持同一对象与状态 | PC-A、无线 B、已确认 IP 和已绘网页跨镜保留 | 数据库可跟同一查询；消息系统可跟同一消息/offset；不要只换本片文字 |
| 用缺少的条件引出下一步 | 自己参数齐了，网站 IP 仍未知；DNS 在远端，所以先补下一跳 MAC | 先提出当前还缺什么，再引入解决它的机制；按新系统事实决定顺序 |
| 结果在事件后出现 | ACK 到达才确认配置；网页内容到达才开始绘制 | 给到达、提交、确认、状态更新规定因果顺序，而非随字幕随意填值 |
| 完整流程后再局部拆解 | “暂停主线”后放大同一 Q1 的帧、五层与传输选择 | 宏观流程与微观机制分别讲，明确回放边界；不是每题都需要五层或历史协议 |
| 动作承担解释，保留读图时间 | 报文移动、字段填入、局部高亮与界面变化；定义段允许静止 | 按需要选箭头、运动、运镜，不用装饰动效维持“每秒都在动” |

## 重点镜头怎么查

时间码针对这里保存的完整成片；实现修订时先映射到 cue id，时间码不是稳定标识。

| 整片区间 | 稳定 cue | 重点观察 |
|---|---|---|
| 01:13–01:45 | mac → discover | 推近原网卡，再拉回原场景；停稳之后才引入新报文 |
| 01:59–02:58 | requestack / dhcp_recap / udp_ports / configuration | 首次交换、时间回放、UDP 端口拆成不同镜头；回看时参数仍有效 |
| 02:58–04:25 | why_dns / arp / dns / web | 因果链、MAC 双行卡片、移动通道避开字段，以及接收之后更新状态 |
| 04:25–05:40 | replay / frame / layers / udp | 明确局部回放，同一查询逐层封装，UDP/TCP 是并列选择 |
| 05:40–06:29 | unplug / effects / replug | 网页与旧配置可留，新请求受阻；恢复不必换新 IP |
| 06:29–07:06 | rarp_bridge / rarp | 明确切换另一历史设备；查表、回复、填入自己的 IP |

## 保留返工教训

1. **先核对状态与叙事时间**：早期 01/02、拿配置、RARP 的衔接不清，后来用明确前提、状态与历史对照修复。不要从最终画面倒推“初版一次成功”。
2. **同时看容器和运动过程**：MAC 标签和值挤在同一行、LAN/WAN 缺边距、越框紫线，以及报文经过字段，是不同问题。修复包括双行卡片、内缩标签、删除无必要线路、上移报文通道。画布内不等于卡片内，也不等于没有途中遮挡。
3. **术语先小段试听**：本用户要求 TCP 等常用缩写与中文名称对应；MAC 地址最后采用自然连读，逐字母方案曾被指出卡顿。这是本次读法选择，不是所有缩写的通用拼读规则。
4. **只改实际受影响的声音**：ARP 局部重录并单独轻度降噪，其余实际选中的声音保留；新任务音色仍按本轮选择与工程 profile 解析，参考片旁白不替代声音选择流程。
5. **观察时间来自实际动作和声音**：DHCP 回放的消息运动约 2–3 秒，MAC 推拉各 2.1 秒，都是本片选择；新片应按信息量和预演判断，不固定套数值。
