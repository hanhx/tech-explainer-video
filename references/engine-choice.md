# 选择制作引擎

先完成导演阐述和分镜，再选工具。问题不是“用哪个工具”，而是“这些镜头需要什么能力”。同一部片子可以混合：例如 Manim 做算法推导段落，Remotion 做片头和字幕包装，最后 ffmpeg 合成。

用户已指定工具时，按其选择执行；如果所选工具明显不适合某些镜头，说明代价并给出替代建议，由用户决定。

## 决策顺序

1. **列出分镜中最难的 2–3 个镜头**（高潮镜头一定在内），看它们落在表中哪一列最强。
2. **看整体风格**：几何/数学/示意图 → Manim 或 Motion Canvas；界面/排版/品牌包装/数据模板 → Remotion；位图角色/贴纸/像素 → 逐帧绘制或 Remotion+SVG；需要实拍和精修 → GUI 软件。
3. **看环境与成本**：本机已有哪个环境、用户是否熟悉、是否要批量生产、是否需要后续由人在 GUI 里精修。不要为一个片子临时搭建重环境，除非收益明显。
4. **混合时定好边界**：每段用一种引擎输出带透明或纯色背景的视频片段，统一时间轴（project.json 的 cue 时间）和音轨，最后由 ffmpeg 合成。
5. 把选择和理由写进 storyboard.md 开头一行，例如：“引擎：Manim（主体是 B+ 树的分裂与查找，需要连续变形）；片头用 Remotion。”

## 常见情形

| 主题 | 建议 | 理由 |
|---|---|---|
| 梯度下降、注意力矩阵、傅里叶变换 | Manim | 公式、坐标、连续变形是核心 |
| B+ 树、排序、红黑树、哈希冲突 | Manim / Motion Canvas | 结构变化需要对象身份连续 |
| “一个 HTTP 请求的一生”（浏览器、DevTools、终端） | Remotion | 需要逼真复刻界面和代码 |
| TCP 握手、Kafka 分区、K8s 调度（示意图） | Manim 或 Remotion 皆可 | 偏几何选 Manim，偏卡片/界面/品牌风选 Remotion |
| 卡通角色对话、贴纸、像素风 | 逐帧绘制 或 Remotion + SVG | 位图合成和口型更直接 |
| 每天 20 条“一分钟一个命令”系列 | Remotion | 模板 + 数据批量渲染 |
| 产品发布宣传、需要实拍 | GUI 软件 / Remotion | 素材剪辑与精修为主 |

## 本 Skill 的支持范围

本 Skill 自带的时间轴、配音、校验脚本（build_timeline / synthesize / verify_video）与引擎无关：它们只依赖 project.json、逐句音频和成片 MP4。`render_project.py` 和 starter 针对 Manim；`scripts/pillow_engine.py` 是不依赖 Manim 的逐帧引擎（Pillow + NumPy + ffmpeg），自带按停顿对齐的词级触发、推拉镜头、交叉淡化、字幕、音效与可选配乐混音。选择其他引擎时：

- 复用 `synthesize.py` 生成配音，`build_timeline.py` 产出 timeline.json，作为该引擎的输入（Remotion 可直接 `import timeline.json`，用 `start_s * fps` 定位 `<Sequence>`；音频用 `<Audio>` 按 cue 放置）。
- 渲染后同样写出 `actual-timeline.json`（字段见 implementation.md），即可用 `verify_video.py` 做技术验收。
- 本机没有该引擎环境时，先告知用户需要安装什么、大致耗时，不静默安装。
