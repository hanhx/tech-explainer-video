# 用画面讲解，而不是用文字讲解

本文件回答一个问题：怎样让成片像“动画讲解”，而不是“会动的 PPT”。它优先于模板习惯；与用户已选风格冲突时以用户选择为准。

## 1. 文字预算（默认硬约束）

旁白负责解释，画面负责展示，屏上文字只负责命名。【研究：Mayer 冗余/通道原则】

| 层 | 默认 | 说明 |
|---|---|---|
| 字幕 | 1 层，跟随声音 | 唯一允许出现整句的地方 |
| 镜头标题 | 可选，≤ 12 字，问题或名词短语 | 不再加副标题；副标题内容交给旁白 |
| 对象标签 | 2–6 字，贴着对象 | 名词，不写完整句子 |
| 说明句/横幅/图注 | 默认 0 | 需要时只在一镜中短暂出现，并替代而不是叠加标题 |
| 章节导航、页码 | 默认关 | 只在章节切换时出现 1–2 秒；用户要求常驻时再常驻 |

同屏可读文字（不含字幕）建议 ≤ 20 字。【经验】超出时先问：这句话能否改成一个动作、一次高亮或一个对比？

**反例**（DeepInfer V20 第 22 镜）：标题 + 副标题 + 横幅 + 图注 + 字幕 = 5 层同义文字，观众读字就看不到格子在变化。改法：只留“同一个字，每层都在加工”这一标题与字幕；“行=层、列=位置”用逐行点亮和逐列扫过演示出来。

## 2. 去文字测试

分镜和 draft 阶段各做一次：隐藏字幕与所有说明文字（保留对象标签），静音只看画面。

- 能看出“谁在动、什么变了、结果去了哪里”→ 通过。
- 只能看到静止方框，信息全在文字里 → 这一镜没有画面讲解，必须重设计，不能靠改字解决。

## 3. 每个机制先找“视觉事件”

每一镜在分镜表里写出一个**视觉事件**：观众不读字也能感知的变化。常用类型：

| 事件 | 适合表达 | 例子 |
|---|---|---|
| 流动/搬运 | 数据从哪到哪 | token 小方块从输入飞入模型，逐层上升 |
| 累积/填满 | 缓存、队列、容量 | 显存条一格格填满，满了变红并挤出旧块 |
| 复用/复制 | 缓存命中、共享 | 已算好的块直接亮起被“拿走”，而重算路径变灰 |
| 对比/分屏 | 优化前后、两种策略 | 左右同任务同步播放，一边先完成 |
| 规模反差 | 数量级 | 1 个点 → 拉远变成 100 万个点 |
| 变形 | 同一对象换视角 | 一行文字变形为一列格子（保持对象身份） |
| 失败/冲突 | 为什么需要这个机制 | 两个请求抢同一块，碰撞抖动 |

高潮镜头必须是一个视觉事件，而不是一句结论文字。动作服务于因果：每个动作都能回答“这一下说明了什么”。

## 4. 灰框不是画面

- 空状态用浅色，但**会被讲到的对象**要有可识别的形状、颜色或图标，不要全片统一灰色圆角框。
- 重要对象首次出场给一个“亮相”（放大回弹/描边生长），之后保持外形不变以便追踪。
- 同一时刻画面上只有一个“正在发生”的区域；其他区域降低饱和或透明度。

## 5. 运镜与转场

- 静态整页切换是最后手段。优先：推近看细节、拉远看全局、平移跟随数据、对象变形过渡到下一镜。
- 章节内尽量不硬切；用上一镜的终态对象作为下一镜的起点（match cut）。
- 每 15–30 秒至少有一次镜头尺度变化（全景↔特写），避免全片同一机位。【经验】

## 6. 节奏要有起伏

- 不要每镜都是“说完 + 固定保持”。铺垫和已知内容可快切（1–2 秒一个状态），高潮前留 0.5–1 秒静默，高潮本身放慢并保持更久。
- 在分镜表里给每镜标“快/中/慢”，检查是否连续 4 镜以上同一档。

## 7. 声音设计默认开启

连贯原则反对的是**无关**的音乐与趣闻，不是所有声音。默认：

- 低音量背景音乐（旁白期间比人声低约 18–25 dB 并闪避），风格与画面一致；用户明确不要时关闭。
- 3–5 种短音效只给状态变化：出现、到达、命中、失败、完成。
- 高潮/结论前用音乐短暂停顿或降低制造注意力。

实现：在 `project.json` 加 `"music": {"file": "assets/bgm.mp3", "gain_db": -22, "duck": true}`，`render_project.py --mode final` 会循环、压低并在旁白处闪避。音乐素材须有合法授权并记录来源；无可用素材时说明缺口，不自行生成冒充成品。

## 8. 先找对标片

分镜前选 1 个对标作品或风格方向（如 3Blue1Brown 的连续变形、Kurzgesagt 的扁平角色与场景、ByteByteGo 的流程动画、Fireship 的快切），写下要借用的 3 点：

1. 每屏文字量与位置；
2. 画面变化频率与转场方式；
3. 配色与对象造型。

只借方法，不复制具体素材。用户给了参考时按 [参考迁移](reference-style-review.md) 拆解。

## 9. 观众视角审片

技术检查之外，每轮 draft 必做：

1. **接触表（contact sheet）**：用 `scripts/contact_sheet.py` 每镜取动作前/中/后 3 帧拼成一张图，实际看图并逐镜记录：焦点是否唯一、同屏文字字数、是否有视觉事件、是否与上一镜机位相同。
2. **零上下文复述**：把关键帧序列 + 字幕交给一个没有本项目上下文的子代理（或请用户找人），请其复述机制。复述错或空缺的地方，就是没讲通的镜头；先修画面再修文案。
3. 只有用户或真实观众的反馈能说“看懂了”；复述测试只用于找问题。
