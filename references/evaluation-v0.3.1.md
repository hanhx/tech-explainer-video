## 复述审查带来的修改

先后两次独立、无背景审查只读取接触表，不读取源码或预设答案：

- 第一轮发现“开启防抖后旧请求消失”可能暗示撤销历史请求，已改为保留并降低其视觉权重；“持续输入”字幕与停止后发出的状态相冲突，已拆开条件阶段。
- 第二轮能复述输入等待、停止后发送、旧请求保留；6 段中 5 段“懂”、1 段“半懂”。半懂来自自动抽帧未拍到归零瞬间；另发现审查标题沿用了上一阶段名称。
- 因此补充 cue 级 `review_times_s`：明确抽取新字符出现前、归零时、再次转动后；更新阶段标题，并将新请求起点移到输入框外，避免遮住原查询。

修改后的复核由第二位审查者继续完成，六段均给出“懂”，归零、停止等待与再次发出的条件变化可见；这是修订复核，不计为第三次独立盲测。仍指出第二次发送中途短暂贴近旧请求，后续状态可消除歧义，未列为理解阻断。模型复述关卡通过。

最终复核结果与源文件/输出哈希保存于本次本地评估工程；仅以实际记录中的文件为准。结构检查、像素检查和模型复述不代表真实观众已理解或认为流畅。

## 可复现源码

源码在 `assets/examples/debounce-actions-v1/`，无需私人声音、模型或外部音效；只依赖已有 Pillow、NumPy 与 FFmpeg。素材媒体不收入 Skill。

```sh
cp -R "$SKILL/assets/examples/debounce-actions-v1" "$PROJECT"
"$PY" "$SKILL/scripts/pillow_engine.py" "$PROJECT" --draft
"$PY" "$SKILL/scripts/contact_sheet.py" "$PROJECT/out/draft.mp4" \
  --timeline "$PROJECT/out/actual-timeline.json" --output "$PROJECT/out/contact.png" --at-events
```

`--draft` 是低帧率布局预演；检查运动应以项目设定的原生帧率输出专项样段。示例的计时值用于看清机制。技术语义依据 [MDN Debounce](https://developer.mozilla.org/en-US/docs/Glossary/Debounce)，2026-11-06 核对：本例演示尾沿触发，输入停够指定间隔后执行，不代表所有防抖配置。
