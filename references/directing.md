# 导演、视觉与分镜

像导演一样工作：先决定观众在每一秒**看哪里、理解什么、感受什么**，再决定怎么画、用什么工具画。

## 依据等级

每条规则后标注来源等级，决定它能否当硬约束：

| 标记 | 含义 | 如何使用 |
|---|---|---|
| 【规范】 | 行业标准或平台规范，本 Skill 维护时已核对原文 | 默认遵守，偏离需说明理由 |
| 【研究】 | 学术研究结论，本 Skill 维护时**未逐条核对原文** | 作为强默认；引用到交付物前应自行核对 |
| 【惯例】 | 影视/动画/设计行业通行做法 | 默认遵守，可按风格调整 |
| 【经验】 | 本 Skill 作者的经验值，无可靠出处 | 只作起点，以动态预演和观看反馈为准 |

## 1. 导演阐述（动手前确定）

| 项 | 示例（TCP 三次握手） |
|---|---|
| 观众 | 刚学网络的后端新人，知道 IP，不懂状态机 |
| 一句话目标 | 看完能说清“为什么是三次，不是两次” |
| 要打掉的误解 | “握手就是互相打招呼，次数无所谓” |
| 情绪曲线 | 好奇 → 跟上 → 恍然（旧 SYN 反例）→ 收束 |
| 高潮镜头 | 过期 SYN 到达，服务器傻等；第三次握手 RST 掐断 |
| 开头承诺与画面 | 首屏尽快给相关吸引点；前3–5秒以问题/效果和具体观看承诺让人愿意继续，可声画并行融合；标出实际时间及正文兑现位置 |
| 正文续看节点 | 阶段收获、下一疑问和相关画面；长片覆盖多个关键阶段转换 |
| 结尾收获与传播 | 回扣开头，点明具体收获，按用户选择自然邀请；未指定时默认一个相关行动 |

先找到让观众恍然大悟的画面，其余镜头为它铺垫。【经验】

## 2. 学习科学：画面与旁白怎么配合 【研究】

以下来自 Mayer 的多媒体学习原则（Mayer, *Multimedia Learning*, 2nd/3rd ed.；Clark & Mayer, *e-Learning and the Science of Instruction*）。原则名称与大意为学界公认；具体效应量与边界条件请查原书。

| 原则 | 在技术视频里的做法 |
|---|---|
| 连贯（Coherence） | 删掉与目标无关的装饰、趣闻；低音量配乐和状态音效不算无关（见 [visual-craft.md](visual-craft.md) §7） |
| 提示（Signaling） | 用高亮、箭头、放大指出旁白此刻说的对象 |
| 冗余（Redundancy） | 有旁白+图时，屏上不放同义的副标题/横幅/图注；只留字幕 + 短标题 + 对象标签（文字预算见 [visual-craft.md](visual-craft.md) §1） |
| 空间邻近（Spatial contiguity） | 标签贴着对象放，不放在远处图例里 |
| 时间同步（Temporal contiguity） | 旁白说到某词时，对应画面同时出现 |
| 分段（Segmenting） | 复杂过程拆成短段，每段一个新理解，段间有停顿 |
| 预训练（Pre-training） | 先介绍出场对象与名称，再讲它们的交互 |
| 通道（Modality） | 解释用语音，画面用图形，避免让观众同时读长文字又看动画 |
| 个性化（Personalization） | 对话式口吻（“你”“我们”）优于书面腔 |
| 声音（Voice） | 自然人声优于机械合成声；TTS 需试听把关 |

视频长度与形式：Guo, Kim & Rubin（2014，Learning@Scale，MOOC 观看数据）报告较短视频（约 6 分钟以内）观看完成度更高、边画边讲（Khan 式）比静态幻灯片更吸引人、语速较快且有热情的讲述者参与度更高。此为 MOOC 场景观察性研究，用于短视频需谨慎类推。【研究】

## 3. 结构

1. **钩子**：开头先抛一个反常识问题或可见痛点，而不是先放大标题。【惯例】
2. **建立**：介绍出场对象和规则（对应“预训练”）。【研究】
3. **展开**：按因果推进，每镜一个新理解（对应“分段”）。【研究】
4. **反转/对比**：反例、失败情况、前后对比。【惯例】
5. **收束**：回到开头的问题，给一句可复述的结论。【惯例】

“同屏新元素不超过 3 个”是工作上限，不是研究结论。【经验】

开头吸引、正文续看、结尾收获与传播为本 Skill 的制作要求，与分镜同级；详细做法见 [观看设计](audience-design.md)。这是用户要求的创作约定，不是平台算法规则或已验证的留存提升保证。

## 4. 动态分镜（Animatic）先于正式制作 【惯例】

动画行业在故事板之后、正式动画之前做 animatic：静态分镜帧按粗配音时间排成视频，用来提前发现剧本、机位、镜头表和时间问题，修改后反复审，直到分镜锁定。

本 Skill 的对应做法：
1. 每镜 1 张关键帧（静态样张）→ 与用户确认风格和构图。
2. 用**实际配音**（或临时 TTS）+ 关键帧按 timeline 拼成 animatic（关键帧淡入淡出即可）→ 审节奏、镜头顺序、哪些能删。
3. 锁定分镜后再做正式动画。改分镜的成本远低于改成片。

## 5. 镜头语言 【惯例】

| 镜头 | 用途 | 技术视频里的对应 |
|---|---|---|
| 全景 / 建立镜头 | 交代全局关系 | 完整架构图、两端主机+链路 |
| 中景 | 主体间交互 | 两个组件和它们之间的数据流 |
| 特写 | 一个字段、一个值、一个状态 | 放大 `ack=x+1`、计数器从 2 变 1 |
| 推 | 引导注意到细节 | 从系统推到一条记录 |
| 拉 | 揭示细节在整体中的位置 | 从一行数据拉到整棵树 |
| 跟 | 追踪移动对象 | 跟着数据包穿过多层 |
| 固定 | 比较、阅读、思考 | 前后状态并排 |

- **180 度规则 / 画面方向**：两个主体的左右关系跨镜头保持一致（客户端始终在左）；越轴会让观众迷失方向。必须越轴时用一个中性镜头或明确的运镜过渡。
- 每次运镜都要能说出“为什么动”，说不出就固定。
- 镜头移动时不出新信息；先移动、停稳，再出新东西。【经验】
- **对象连续（Object constancy）**：同一数据对象在过渡中可被追踪，能减轻认知负担；不要让变形暗示两个不同实体是同一个。【规范：Bostock, Object Constancy】

## 6. 构图与视觉层级

- **舞台调度（Staging）**：任一时刻只把注意力导向最重要的东西。【惯例：迪士尼动画十二法则】
- **格式塔分组** 【研究，知觉心理学通用】：
  - 接近：相关的东西放近，无关的拉开。
  - 相似：同类对象同色同形。
  - 共同命运：一起移动的东西被看作一组——同一批数据包一起动，不同批次错开。
  - 连续：连线和箭头用平滑路径，观众会沿线追踪。
  - 封闭：用框或底色把一组对象围起来表示“同属一个系统”。
- **三分法、引导线、视觉重量平衡**：主体放在三分线交点附近；用连线、视线、运动方向把视线引向焦点；左右视觉重量大致平衡。【惯例】
- **三层**：背景（低对比）→ 内容 → 信息层（字幕、标题、HUD，固定位置不随镜头动）。【惯例】
- **颜色**：一种颜色只表达一类含义，全片不变。**颜色不能是唯一的区分手段**（成功/失败同时用图标或形状区分）。【规范：WCAG 2.2 SC 1.4.1】
- **对比度**：文字与背景对比度至少 4.5:1，大字至少 3:1。【规范：WCAG 2.2 SC 1.4.3】
- **闪烁**：任何一秒内闪烁不超过 3 次（错误提示、爆炸特效、转场闪白都要注意）。【规范：WCAG 2.2 SC 2.3.1】
- **安全区**：重要内容离边缘至少 5%；竖屏避开平台 UI 区域。具体像素以目标平台规范为准。【经验】
- **留白**：拥挤时拆成多个镜头，不缩小字号。【经验】

## 7. 字幕 【规范：Netflix 简体中文字幕规范】

- 每行最多 **16** 个汉字，最多 **2** 行。
- 阅读速度：成人内容不超过 **9 字/秒**，儿童内容 7 字/秒。旁白语速过快导致字幕超速时，精简字幕而非删内容（spoken_text 与 subtitle 分开）。
- 标点：不用逗号和句号，用空格代替；问号、感叹号用全角；省略号用 “…”（U+2026）。
- 这是流媒体影视规范；短视频平台常把整句压在一行，可按平台惯例调整，但字数与速度上限仍是好的默认。

字号：1080p 下字幕约 40–48px、标签 ≥ 28px，仅作起点；按本轮目标尺寸实看，包含手机时再做手机尺寸复查。【经验】标题/导航与字体图标详见[视觉层级](visual-hierarchy-and-timing.md)。

## 8. 动效

**动画原则** 【惯例：Thomas & Johnston, *The Illusion of Life*, 1981】 选用与技术视频相关的：

| 原则 | 技术视频里的用法 |
|---|---|
| 预备（Anticipation） | 数据包发出前轻微后缩，提示“要动了” |
| 舞台调度（Staging） | 同上，单一焦点 |
| 缓入缓出（Slow in/out） | 几乎所有移动都用缓动；只有机械过程（扫描、计时）用线性 |
| 弧线（Arc） | 飞行的数据包走弧线更自然；示意图中的严格路径（流水线）走直线 |
| 跟随与重叠（Follow through） | 卡通、贴纸风可用；严肃示意图慎用 |
| 次要动作（Secondary action） | 角色眨眼、呼吸；不得抢主动作 |
| 时间节奏（Timing） | 帧数决定重量感：重要变化慢一点，次要变化快一点 |
| 夸张（Exaggeration） | 关键状态变化（计数 2→1）可以放大强调 |

**缓动**：进场用减速曲线、出场用加速曲线、屏内移动用标准曲线；动画距离/面积越大，时长越长。【规范：Material Design motion】

**时长**：Material Design 的 UI 时长刻度是 50–1000ms（短 50–200、中 250–400、长 450–600、特长 700–1000），典型屏幕转场约 300ms，淡入约 150ms。【规范】
注意：这是**交互界面**规范，用户自己触发、已知道要看什么。讲解视频里观众需要先发现、再理解变化，通常要更慢：小元素 0.3–0.5s、对象移动 0.6–1.2s、镜头运动 1–2s。【经验，以动态预演为准】

**错峰**：一组元素依次出现比同时出现更易读，间隔约 80–150ms。【经验】

**运动即含义**：移动方向=数据流方向；变形=“还是同一个东西”；淡出=不再相关；抖动=异常。【惯例】

## 9. 剪辑与节奏

- **Walter Murch 的“六条法则”**（*In the Blink of an Eye*）按优先级给出剪辑点决策：情感 > 故事 > 节奏 > 视线追踪 > 二维画面平面 > 三维空间连续。书中给出的权重约为 51/23/10/7/5/4%。【惯例；本 Skill 维护时未核对原书】
  技术视频的转译：**理解（故事）优先于炫技**；剪辑点要让观众视线自然落到下一个焦点上（视线追踪）。
- **在动作中切**：章节内转场尽量借对象的运动完成，比硬切更顺。【惯例】
- **节奏有快有慢**：铺垫段可快，关键结论处放慢并留白。高潮镜头前后的节奏对比比整体均速更有效。【惯例】
- 全片平均镜头长度没有通用标准；以“每镜一个新理解是否已被看清”为准。【经验】

## 10. 声音设计

- **响度**：成片按目标平台标准化。广播标准为 **-23 LUFS（±1 LU），真峰值不超过 -1 dBTP**；流媒体在没有响度元数据时，EBU 建议分发响度在 **-20 至 -16 LUFS** 之间。【规范：EBU R128 (2023)、R128 s2 (2023)】
  本 Skill 的 `render_project.py` 默认 `loudnorm I=-17 TP=-1.5`，处于该区间内，适合手机/网页播放；面向广播交付时改为 -23。
- **音乐与旁白的相对电平**：没有统一标准。常见做法是旁白期间音乐比旁白低约 15–25 dB 并做闪避。【惯例/经验】
- 旁白说到哪个词，画面就在那一刻变化（时间同步原则）。【研究】
- 音效只给状态改变的瞬间；一个视频 3–5 种音效足够。【经验】
- 关键结论前留 0.5 秒左右静默。【经验】

## 12. 导演审片清单

预演（animatic、draft）和成片都按此表看：

- [ ] 首帧/前2秒是否有目标观看尺寸上可辨认的相关吸引点？连看真实声音与画面的前3–5秒是否有停留、继续看的理由，观看承诺是否与钩子自然融合并进入过程，且匹配标题/封面与正文兑现？是否避免为卡时限提速、堆字或机械加片头？
- [ ] 正文在主要阶段转换兑现收获并给出下一步理由？长片是否有多个分散的续看节点？调侃/小测试后是否自然回到机制？
- [ ] 结尾是否回扣开头、点明具体收获，再以条件式表达邀请一个相关行动？是否让观众判断是否受益，且服从本轮指定文案/动作？未指定时收敛邀请，选择分享时说明对象和理由。
- [ ] 上述设计是否出现在真实配音与实际画面里，而不只是分镜或报告的文字？
- [ ] 关掉声音只看画面，能看懂大意吗？只听声音，知道画面在指什么吗？（通道/时间同步）
- [ ] 每个镜头焦点唯一吗？视线是否被引导到旁白所指之处？（提示/舞台调度）
- [ ] 有没有画面先于旁白剧透，或旁白说完画面还没到？
- [ ] 主体左右方位、颜色语义全片一致吗？颜色是否是唯一区分手段？
- [ ] 字幕：每行 ≤ 16 字、≤ 9 字/秒？对比度 ≥ 4.5:1？一秒内闪烁 ≤ 3 次？
- [ ] 最密集的一帧在本轮目标观看尺寸还能读吗？目标包含手机时才检查手机适配。
- [ ] 高潮镜头有足够停留吗？节奏有快慢对比吗？
- [ ] 有没有与目标无关的装饰、镜头可以删？（连贯）
- [ ] 去文字测试：隐藏字幕与说明文字后，每镜是否仍有可见的视觉事件？同屏非字幕文字是否 ≤ 20 字、没有副标题/横幅/图注叠加？
- [ ] 是否像幻灯片：常驻导航/页码、每镜同一机位同一版式、整页硬切？（见 [visual-craft.md](visual-craft.md)）
- [ ] 有低音量配乐与状态音效吗（用户未拒绝时）？
- [ ] 成片响度符合目标平台吗？

结论按“时间码—问题—依据—修改建议”列出。没有真实观众测试时，不声称“观众能理解”。
