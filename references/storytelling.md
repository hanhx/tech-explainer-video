# 分镜、构图与运镜

> 镜头语言、构图、动效、字幕、声音的完整规则与出处见 [directing.md](directing.md)；本文聚焦“用视觉方法讲清机制”。

## 讲解目标

先写一句“看完后观众能解释什么”，再列出一个常见误解。保留完成这个目标需要的背景知识；不要把主题的所有名词都讲一遍。开头吸引、正文续看、结尾收获与传播是与分镜同级的必备设计，具体组织见 [观看设计](audience-design.md)；不固定镜头数或时长。

分镜至少包含：

| 项目 | 要回答的问题 |
|---|---|
| 目的 | 这一镜头增加哪一条理解？ |
| 旁白/字幕 | 说什么？屏幕上的精简表达是否仍准确？ |
| 对象与初态 | 哪些对象已存在？它们代表什么？ |
| 动作与终态 | 什么改变，什么必须保持？ |
| 镜头 | 为什么要缩放、移动或保持固定？ |
| 停顿 | 观众要在这段时间辨认、追踪还是比较？ |
| 衔接 | 下一个镜头如何接住已有对象或问题？ |
| 观看作用 | 这一镜在引入、兑现、续看衔接、节奏调节或收束传播中承担什么？ |

分镜前先在 `storyboard.md` 写观看设计总表：开头承诺及对应首屏、正文阶段收获与续看节点、结尾可复述收获及分享/参与邀请。每项绑定实际 cue 与画面，不能只写“加钩子/加互动”。

## 选择视觉方法

- **层级揭示**：一条记录 → 所属结构 → 更大系统。适合包含关系和尺度变化。缩放后改变细节层次时保留可识别的颜色、名称或编号。
- **对象连续**：移动或变形既有对象，让观众能追踪“还是同一个”。不要用变形暗示不存在的实体等价关系；逻辑视角切换到部署视角时应明确提示。
- **固定镜头、逐步建立关系**：分工、依赖、请求流和所有权关系，先出现对象，再按解释顺序建立连线，完成后保持。
- **变化与不变的对比**：移动一个指针，同时保留另一个；删除一条引用，同时保留仍被引用的对象。把不变项也设计为明确的视觉证据。
- **聚焦与回看**：放大关键局部回答问题，再回到总览说明影响。只有回看能增加理解时才返回。

这些是信息可视化和动画讲解手法，不等于经过专业导演审核。不要为了“电影感”增加无意义的移动。

## 节奏

音频长度是底座，观察时间是编辑决策。把过场、动作、辨认编号、读关系、比较前后状态分开考虑。

- 新关系复杂时，分步出现或拆句；不要只把一幅密集图保持更久。
- 旁白可以覆盖简单动作；关键结论最好有稳定的完整画面。
- 数字或术语被点名时再突出对应对象，避免提前显示后续状态。
- 动作结束与声音结束后仍要比较时，显式留出观察保持。
- 例子中的 0.6 秒箭头、1.5 秒章首或 1.8 秒结尾是该片的选择，不是通用标准。

## 动态预演与检查

低分辨率动态预演用于检查动作顺序、镜头速度、视线跳转和节奏；静态帧用于检查字号、边界和遮挡。对旁白提到的关键对象，检查动作前、中、后的实际成片帧。

先问“观众是否能指出哪条关系改变”，再评价装饰。没有观众测试时，不声称停顿已证明能让人理解。

参考：[Object Constancy](https://bost.ocks.org/mike/constancy/)、[Manim MovingCameraScene](https://docs.manim.community/en/stable/reference/manim.scene.moving_camera_scene.MovingCameraScene.html)。
