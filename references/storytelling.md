# 分镜、构图与运镜

> 镜头语言、构图、动效、字幕、声音的完整规则与出处见 [directing.md](directing.md)；本文聚焦“用视觉方法讲清机制”。

## 讲解目标

先写一句“看完后观众能解释什么”，再列出一个常见误解。保留完成这个目标需要的背景知识；不要把主题的所有名词都讲一遍。开头吸引、正文续看、结尾收获与传播是与分镜同级的必备设计，具体组织见 [观看设计](audience-design.md)；不固定镜头数或时长。

分镜至少包含：

| 项目 | 要回答的问题 |
|---|---|
| 目的 | 这一镜头增加哪一条理解？ |
| 旁白/字幕 | 说什么？屏幕上的精简表达是否仍准确？ |
| 对象与初态 | 哪些对象已存在？它们代表什么？ |
| 动作与终态 | 什么改变，什么必须保持？ |
| 镜头 | 为什么要缩放、移动或保持固定？ |
| 停顿 | 观众要在这段时间辨认、追踪还是比较？ |
| 衔接 | 下一个镜头如何接住已有对象或问题？ |
| 观看作用 | 这一镜在引入、兑现、续看衔接、节奏调节或收束传播中承担什么？ |

分镜前先在 `storyboard.md` 写观看设计总表：开头首帧/前2秒吸引点、前3–5秒实际声画的停留理由与具体观看承诺（可融合）、随即进入的过程、正文阶段收获与续看节点、结尾按“回扣开头 → 点明具体收获 → 条件式邀请 → 一个相关行动”组织。每项绑定实际 cue 与画面，不能只写“加钩子/加互动”。

## 从对象和操作推到结论

观众追问“某某是什么”“这一步为什么有用”时，先检查缺了哪个前提，不只追加定义或免责声明。为关键机制补齐以下关系，再决定是否需要改稿或新镜头：

| 关系 | 分镜应让观众看见什么 |
|---|---|
| 角色与任务 | 谁产生输入、谁执行、谁消费结果；先绑定可辨对象，再叠加缩写和优化名称 |
| 实际工作 | 执行过程中究竟计算、读取、传输或判断什么；进度条、勾叉和变色不能独自替代关键操作的解释 |
| 条件与结果 | 初态是什么，为什么这一步现在有必要，结果何时生效；预测、已送去执行、已正式接纳应分清 |
| 收益与代价 | 哪项工作减少、复用或重排，为什么可能影响时间/资源；与什么基准、在什么条件下比较 |
| 兑现与延伸 | 机制讲完及时回答最初问题，再延伸开放实现、部署用途或其他适用场景；避免先绕进外围配置 |

DeepInfer V20先交代执行开销和批量机会，再讲草稿与验证；依赖段先用同一份请假申请解释信息加工用途，再映射到网格和输入/输出，之后才追上游与解释局部近似。具体材料见[案例](example-deepinfer.md)。迁移的是补齐前提的方法，不要求其他主题都有模型、缓存或成本结论。

同一案例应贯穿主要操作与结尾，示例文本也与场景相符；加入第二个请求或回到过去步骤时明确引入。讲“已有A，为什么研究B”应说明共同任务及B的具体执行选择，不从另一个实现存在推导替换必要性、独占创新或整体领先。所有权、首创性与实测收益分别核实。

依赖图标清层序/时间序，以及箭头表达的是正向执行、数据流还是反向追溯；重建后层状态时，所需历史可能向更早层扩大。局部省略或近似时，让仍在参与的全局信息保持可见。方向按真实机制决定，不把本例上下布局当作所有图的规定。

## 从具体用途映射到图，而不是从图猜用途

技术准确和观众能跟上是两件事。写关键段时，用分镜中已有的一行记录：**观众已知 → 这一步要解决的问题 → 同一案例的输入/加工/结果 → 图形对应 → 下一步为什么需要它**。简单镜头可融合，不增加独立表单或确认流程。

- **先回答正在问的问题。** “为什么要多层”需要看到逐步组合信息的用途；“平均三个数”能演示数据依赖，却没有说明模型为什么这样加工。数值例、公式或类比是否合适，由受众和当前缺口决定。
- **一个主案例接住抽象化。** 例如请假申请→申请人/日期/时长→完整事项→联系教学制度。再让同一句话的文字位置进入层×位置网格，把格子说明为加工后的状态。另开第二请求、历史回放或新类比时交代关系；不要在关键桥接处无提示换到水果或另一业务。
- **教学分阶段与真实结构分别命名。** “提取线索、组合事项、联系制度”说明信息加工用途，可由多层共同完成；不把它逐一写死为真实模型的第1/2/3层职责。用中文注释说明状态含义时，说明它是示意，不是实测内部文字或固定特征分工。
- **依赖先正向演一次。** 让前一步的结果真正被后一步读取、加工，再写出新结果；随后再逆向问“为准备目标，还需要什么”。行列、层序、执行方向、逆向追溯箭头各自命名。同一张全局蓝色条不能让观众误以为上层输出已经不再需要。
- **近似要看见省掉了什么。** 显示哪条读取/哪部分操作退出、哪些信息仍保留、结果何时改标近似；再接后续消费者与质量检查。不要从“少算”直接跳到“速度/质量一起评估”两个标签。

## 比较量与结论之间的桥

先说清“同样什么、改变什么、比较什么”。例如同一设备、同样3个已知位置，比较分3轮与合成1批；观众先看见重复权重读取与可共用部分，再理解时间机会。避免用“算得更多却未必更慢、还要看设备”承担整座桥。

工作量、墙钟时间、吞吐、业务成本分别命名。设备/批次等条件要解释它改变了哪项开销，边界接在机制后。已有A而研究B时，区分共同能力、具体实现选择和可验证差别；方法共享、首创性、框架对测和局部策略数据不是同一种证据。涉及训练时，生成候选、参数学习和训练总成本分别核算。

口播优先用正向因果句：“因为省略了这些局部读取，状态变为近似，后续回答就要检查是否受影响。”边界说明用来约束已讲清的结论，避免连续“xxx，不能xxx/却未必xxx”让观众自己补逻辑。保留必要的技术限制，不把简洁误当删边界。

## 观众反馈怎样改变下一步

“这格是什么”先查对象/坐标；“为啥依赖”先查前一步到底提供什么信息；“整体不懂”回到最早断点，不从结尾补更多总结。先在回答中用已有案例讲清，再据此修改最小连贯实际配音样段；上下文被省略时标明是摘录，仍需检查接回整片的衔接。

提问针对当前缺口，例如“能否解释后面的计算为什么要用前面提炼的信息”，不是同时要求评价全部声音、画面与知识。记录具体文件/哈希、问题和回答；“案例懂了但接回模型仍不懂”属于部分理解。明确负反馈仍未解决时，继续修这条桥，不把新词或几何通过当作解决；其余独立工作可继续。得到清楚反馈后保留选段，不反复确认同一项；没有回复不是验收，也不构成自动停工条件。

## 选择视觉方法

- **层级揭示**：一条记录 → 所属结构 → 更大系统。适合包含关系和尺度变化。缩放后改变细节层次时保留可识别的颜色、名称或编号。
- **对象连续**：移动或变形既有对象，让观众能追踪“还是同一个”。不要用变形暗示不存在的实体等价关系；逻辑视角切换到部署视角时应明确提示。
- **固定镜头、逐步建立关系**：分工、依赖、请求流和所有权关系，先出现对象，再按解释顺序建立连线，完成后保持。
- **变化与不变的对比**：移动一个指针，同时保留另一个；删除一条引用，同时保留仍被引用的对象。把不变项也设计为明确的视觉证据。
- **聚焦与回看**：放大关键局部回答问题，再回到总览说明影响。只有回看能增加理解时才返回。

这些是信息可视化和动画讲解手法，不等于经过专业导演审核。不要为了“电影感”增加无意义的移动。

## 节奏

音频长度是底座，观察时间是编辑决策。把过场、动作、辨认编号、读关系、比较前后状态分开考虑。

- 新关系复杂时，分步出现或拆句；不要只把一幅密集图保持更久。
- 旁白可以覆盖简单动作；关键结论最好有稳定的完整画面。
- 数字或术语被点名时再突出对应对象，避免提前显示后续状态。
- 动作结束与声音结束后仍要比较时，显式留出观察保持。
- 整体重排不以更短为默认成绩。去重服务于理解；必要的角色铺垫、操作步骤和读图保持不能为目标分钟数牺牲。保留用户已选语速，复杂关系通过分步或改镜头解决。
- 例子中的 0.6 秒箭头、1.5 秒章首或 1.8 秒结尾是该片的选择，不是通用标准。

## 动态预演与检查

多状态一镜的animatic需有关键状态随实际旁白推进；仅用完成态铺满整句时，报告为静态布局/镜头顺序粗看，后续用动态片验证时序。

低分辨率动态预演用于检查动作顺序、镜头速度、视线跳转和节奏；静态帧用于检查字号、边界和遮挡。对旁白提到的关键对象，检查动作前、中、后的实际成片帧。

先问“观众是否能指出哪条关系改变”，再评价装饰。没有观众测试时，不声称停顿已证明能让人理解。
