# 参考风格的迁移与验收

在用户指定参考片、指出“像素不像像素／只是换色／表现力不够”时读取。

## 先找造成观感的具体设计

读取参考帧与实现，记录字体及设计字号、调色板、线宽和边框、主体尺寸、背景层次、界面、动作节奏、状态反馈。把“好看／游戏感”翻译成可迁移的规则，并指出哪些只是该作品的题材资产。不要求所有视频出现角色、星空、RPG 文本框或背景音乐。

风格切换需重新审视分镜：旧构图是否把新风格限制成换色或替换图标？如果角色、道具或关卡可以承载机制，应设计“识别目标—行动—结果反馈”的动作，再选择组件，而非把一张完整架构图一直摆着。

## 可执行支持

像素场景可用 assets/pixel-kit/pixel_ui.py 的整数格点字体、面板、砖块、精灵和文本辅助函数。它不是指定版式或完整影片模板。选择自己的配色和角色；按主题重写场景。

先检查已有字体；像素中文使用按设计字号整倍数绘制的点阵字体，项目携带许可证。找不到字体时可保留高清字幕层并明确风格折衷，不能用普通黑体阈值化冒充完整点阵字库。不要将个人工程的绝对字体路径写入通用组件。

## 样片与退回条件

对关键动作做短动态样片，长度以能看到完整动作与反馈为准；同时输出与参考同类镜头的对照帧。检查：

- 字体、像素密度、边框、配色和 UI 是否属于一致的视觉系统；字体是否断笔或大小混乱？
- 角色／指示物是否指向当下操作；状态变化能否通过动作和反馈被辨认？
- 背景动效是否抢焦点；关键字段、预算和结果是否可读？
- 是否只是技术图的外观变化，未改善用户已经指出的表现问题？

发现这些具体问题应修正后再交付；不要因可解码、对齐或无遮挡就判定风格通过。报告哪些是实际看帧、连续观看、听音或用户选择的证据。参考作品风格可以迁移，其技术论断仍需单独核实。
