# v0.2.6 验证用例与证据范围

对象是本 Skill 的制作决策和随附脚本，不能只看 SKILL.md 是否通过结构校验。修改版本后记录实际选用的用例、输入、执行命令、产物和结果。

| ID | 输入/场景 | 硬门槛 |
|---|---|---|
| E01 | 静音 starter 的时间轴 | 所有 id 唯一，动作与观察预算可容纳，时长按正式帧率对齐 |
| E02 | 配音文件缺失；或已认可 WAV 内容被改 | 非零退出，报具体 cue，不覆盖已有成功时间轴 |
| E03 | 负数、NaN、重复 cue；动作比旁白长 | 非法时间/id 必须失败；合法长动作应扩大 slot，不能裁掉动作或保持 |
| E04 | 非 Kafka 的引用计数动态小样 | 真正输出可解码 MP4；展开后两条引用可辨；删除 A 后 B 和对象仍在，计数为 1 |
| E05 | 合成非人声测试音频与 cue 绑定 | 输出可解码音视频、SRT 与实际时间轴；可选波形检查能定位对应音频，不可当成 TTS 听感评测 |
| E06 | 用户确认三句，反馈末句异常并选择 B | 只替换指定末句，已认可录音哈希不变；不可把抽样反馈写成全片人工通过 |
| E07 | 用户只问运镜方法，或明确指定 Remotion | 只讨论或尊重指定工具；不能擅自新建/渲染 Manim 工程 |
| E17 | 未指定引擎，主题为“一个 HTTP 请求在浏览器 DevTools 中的一生” | 先出导演阐述和分镜，再依 engine-choice 给出引擎选择与理由（应倾向 Remotion 或说明为何不用）；不默认 Manim |
| E18 | 未指定引擎，主题为“梯度下降在损失曲面上的路径” | 选择 Manim（或说明理由）；分镜有高潮镜头、唯一焦点、运镜理由 |
| E19 | 审片 | 输出按导演审片清单的“时间码—问题—修改”列表，而不只是技术检查结果 |
| E08 | 更换题目制作，例如 DNS 缓存或数据库索引 | 重新核实机制并设计镜头，不能只替换 Kafka 图中文字；动画与旁白对应 |
| E09 | 本机登记个人明快版和 Ono_Anna，分别 resolve；本轮声音覆盖默认 | 两个 profile 的参考哈希、生成条件和 fingerprint 可区分；不改写本机默认；未配置机器仅 list 时返回未配置 |
| E10 | 参考录音被改、profile 不存在、模型错误或缺少对应文字 | resolve 非零退出；不写坏已有解析结果，不回退其他声音，不下载模型 |
| E11 | 用两个解析后的固定参考条件分别生成同一新短句 | 产出可解码音频并记录所选参考、参数和输出哈希；缓存键区分声音；不能把生成成功视为主观相似度或全片听音通过 |
| E12 | 用户指出“地址”或“逐层”平翘舌错误，其余录音已认可 | 定位异常 cue；正文/字幕保留正确文字，读音提示只用于 TTS；固定已选声音条件，只替换实际选中的修复文件，其余 WAV 哈希不变；按新时长更新同步；缺少实际听音反馈不能宣称读音通过 |
| E14 | starter-narrated 运行 synthesize.py 两次；再给一个 cue 加 locked_sha256 并篡改其文件 | 第一次生成全部 cue 并写回 audio 路径；第二次全部命中缓存；篡改后非零退出且不覆盖文件；spoken_text/subtitle 不变 |
| E15 | cue 级 voice 指定两个不同 profile（多角色对话） | 按 profile 分批生成，缓存键/文件名区分声音；工程级 voice_profile 不被单一声音覆盖 |
| E16 | project.json 设置 music.file 后 final 渲染 | 成片含混音音轨，verify --align-audio 仍通过；music.file 缺失时非零退出 |
| E13 | 用户反馈试听“没找到音频”，随后实际听音选择后半段 | 提供可点击音频链接并标明播放顺序；前一反馈不能记成接受；后一反馈只覆盖对应修复句与文件，不能升级为整片人工通过 |

Runner 应记录实际 Agent/脚本、Python/Manim 和相关工具版本。Grader 区分确定性脚本检查、人工看帧、动态观看、听音及独立 Agent 评判。没有授权和隔离条件时不自行启动其他 Agent。

E04 的 starter 小样是已知示例的执行检查，不是盲测或未见题目的泛化证明。E06 的历史修复记录可以用于设计 Skill，但不能作为新 Skill 已成功执行该用例的证据。

E12/E13 的既有“地址”“逐层”修复与反馈是规则来源，可回查实际素材、正文和哈希；这样的历史回放不是新版本 Skill 的独立行为评测。未重新生成并完成实际听音时，不声明新的发音质量测试通过。

新版本需按改动选择相关用例；独立评测或未见主题完整成片没有运行就标记未运行。quick_validate.py 只验证 Skill 结构；不自动运行本表，也不证明视频专业程度、声音一致或观众理解效果。

## 降噪后处理用例

| ID | 输入 | 硬门槛 |
|---|---|---|
| E23 | 对已有代表句与短脉冲执行 afftdn-hiss-v1 | 源文件哈希不变；输出可完整解码；48 kHz 下保持同一帧数、补偿 1200 样本滤镜延迟且尾部不被截断；生成参数/输入输出哈希可追溯；重复指定同一输出报错。真实句与已认可 B 做响度配平对照，不将自动指标写成人工验收。 |
| E24 | 本机 profile 启用降噪；旧句已锁定；另有未启用降噪的 profile | 新 profile 指纹/缓存键改变，旧锁定句不重做；其他 profile 指纹不变；错误预设拒绝；缓存二次运行不再处理；用户反馈仅记为该试听范围。 |

## 局部修订与提前排错

| ID | 输入 | 硬门槛 |
|---|---|---|
| E25 | 同卡标签和值挤在一起、文字在画布内却越过所属容器、运动中途经过字段 | 几何样本检查分别报 overlap / outside_parent 与实际 scene/time；只采首尾不能宣称中途通过。合法嵌套未声明冲突时不误判；缺父节点、非法坐标或格式失败不留下成功报告。 |
| E26 | TTS 中断已有完整原始 WAV；重排/插入 cue；设置 MAC/IP 项目读法和单句覆盖 | 已保存原始音频进入一次后处理、不再调用模型；坏原始文件失败且保留；成功运行固定实际 seed 后插入不使原 cue 换 key；MAC地址连贯映射、IPv4 不误改，显式 tts_text 优先；正式正文不变。可用测试音和受控 worker 验证恢复，但不能当真人 TTS 听感通过。 |
| E27 | Manim 对同一实际短片两次运行 --cache，再不用缓存运行 | 真正生成并解码音视频；原生缓存目录可跨 run 复用，未变片段不重写；保留项目配置；缓存/无缓存解码帧一致；正式 timeline、SRT 和波形可核对。仅检查 CLI 字符串不算通过。 |
| E28 | 用户指出某时间码遮挡和 MAC 卡顿 | 先映射版本与 cue，检查实际声音；局部排版与读法修复，其他实际 WAV 哈希保持；给可试听文件，不能先跑整片再反复找同类问题。可复盘网络片验证规则来源；没有独立新片行为评测时明确未运行。 |
