# 配音、固定参考与听感验收

## 讲述感与手机清晰度

按 [手机人声方案](voice-mobile.md) 分开处理：讲稿的问句/转折/收束、声音条件与实际音轨的清晰度。讲述方向已选时直接沿用，先用实际声音短段合并画面；不能用后期压缩替代语气，也不能把某个 LUFS 数值当作手机户外一定听清的证明。重新合成会改变具体录音；用户认可的试听直接复用并锁定。

## 后端选择与已有素材

优先使用用户指定的音频或 TTS。可接入本地模型、云端服务或剪映导出的逐句文件；核心时间轴只消费音频文件，不依赖某个声音品牌。

本机多音色选择参见 [本机可选音色](voice-profiles.md)：通过注册名称引用固定参考音频，用户本轮选择优先于项目和本机默认。解析配置不是换声完成，实际音频必须来自所选条件。

查找可用环境、模型与已有素材再决定是否需要安装。不要默认重新下载数 GB 权重，也不要把另一台机器的路径写进 Skill。API 凭据由本地环境或现有安全配置读取，不要求用户把密钥贴进对话。

不同 TTS 的同名声音、云端与本地预设不一定相同。通过当前后端实际支持的列表确认可用性，不仅替换一个名字。

## 代表性试听

音色待定或连续听感存在问题时，用少量代表内容做试听：普通句、术语/数字、较长句和段落收尾。比较时尽量统一文本、响度和句间观察空白。

用户已有明确认可的音频时直接沿用；不要每句话重复索要批准。记录反馈所覆盖的具体片段和文件哈希，不把“前三句一致”记成“整片听音通过”。

独立生成的句子即便 speaker、seed 一致，也可能有语调、音高或节奏差异。异常时先定位具体句子；参考录音条件能否改善，要由实际试听验证。声纹分数不能替代这一步。

## Qwen3-TTS 的可选固定参考流程

这是已用过的适配路径，不是所有视频必须使用的后端。CustomVoice 用预设 speaker；需要参考录音时使用支持参考输入的 Base 模型。根据本机安装版本确认 API，下面示意对应 qwen-tts 0.1.1 的调用形状。

~~~python
model = Qwen3TTSModel.from_pretrained(local_model_dir, **runtime_options)
prompt = model.create_voice_clone_prompt(
    ref_audio=selected_reference_wav,
    ref_text=reference_transcript,
    x_vector_only_mode=False,
)
for text in spoken_lines:
    # 重用同一份参考录音、文字与 speaker 条件；采样选项按试听结果调整。
    wavs, sr = model.generate_voice_clone(
        text=text, language="Chinese", voice_clone_prompt=prompt,
        non_streaming_mode=True, **generation_options,
    )
~~~

reference_transcript 必须对应参考录音。不同设备的 dtype、注意力实现和加速方式需要适配，不强制 CUDA、FlashAttention 或某台 Mac 的设置。不要声称固定参考能数学保证每句听感一致。

参考：[Qwen3-TTS 官方示例](https://github.com/QwenLM/Qwen3-TTS#voice-clone)。

## 中文读音局部修复

用户指出平翘舌、声调或术语读错时，先定位 cue 和实际录音，确认目标读音；不要因此换掉整片声音。比如“地址”的址是 zhǐ，“逐层”是 zhú céng：逐为翘舌 zh，层为平舌 c，不能把层也改成 ch。数字、缩写和多音字也按具体上下文核对。

将正式讲稿与合成输入分开保存：正文、字幕、画面使用规范文字；按 cue 记录可选的 `tts_text`、目标读音、修复原因和实际生成条件。后端明确支持读音词典、音素或 SSML 时优先使用其正式接口；不支持时可尝试局部同音字或断句提示。不要把拼音或 SSML 当作所有模型都理解的通用指令，也不要全局替换正文。

本次 Qwen3-TTS 固定参考修复的经验：

| 正式文字 | 正确读音 | 仅传给 TTS 的尝试 | 已有证据与边界 |
|---|---|---|---|
| 地址 | dì zhǐ | 地指 | 用户认可相关八句的发音和声音；不代表其他句子或后端必然有效 |
| 逐层 | zhú céng | 竹层 | 用户在原句/修复句对照中选择后半段；不把“层”换成“成” |

例如项目可保存如下旁路记录，实际由项目的 TTS 适配代码读取；时间轴脚本不自动执行这些提示：

~~~json
{
  "cue_id": "closing-01",
  "spoken_text": "沿着这条线，逐层检查入口、后端和应用监听。",
  "tts_text": "沿着这条线，竹层检查入口、后端和应用监听。",
  "target_pronunciation": "逐层 zhú céng"
}
~~~

保持已选参考录音、对应文字和生成条件，先只重做异常句；参数确需调整时记录变化。缓存键同时考虑合成输入、声音条件与参数，避免读音提示变化后仍命中旧音频。保留旧句，用短对照或已认可的上下文检查目标词、语气和句间衔接。若两三次局部尝试仍无改善，停止机械重试，说明剩余问题；在不改变技术含义且属于用户授权范围时可改写句式，并同步正式讲稿与字幕后重新试听。

试听须附可点击的实际音频文件链接，并说清先旧后新或 A/B 顺序；可同时提供原生播放。用户说“没找到音频”时补链接或打开实际文件，不能把它当成接受，也不要只重复询问。依据实际听音反馈锁定选中的 WAV，复核未修改句的哈希，再用新音频时长更新字幕、动画和停顿。文件哈希、声纹分数、ASR 转写、波形对齐或成功解码都不能证明平翘舌已正确。

持续底噪、空灵/音量反馈、异常空白与倍速要求的分层定位见 [声音与节奏修复](audio-repair.md)；先用同一原始take比较处理链，不直接重录整片。

## 低微底噪与合成伪影

先比较原始句子、混音和成片，区分有声段噪声、段间底噪与额外环境音；响度提升会同时放大已有噪声。用相同片段、配平人声的 A/B 判断清理收益与咬字损伤。用户已认可的处理方案可登记到该 profile 的 `processing.denoise`，执行细节见 [降噪后处理](voice-profiles.md#降噪后处理)。保留原始音频与实际选中试听文件的哈希，避免整片重新合成或重复降噪；反馈只覆盖实际听过的片段。

## 锁定与局部修复

- 对认可的文件计算 SHA256，在 cue 的 locked_sha256 中记录。保留原始文件；需要重采样时同时记录源文件和输出文件的哈希。
- 更换文本、生成参数或参考录音后，旧缓存是否仍有效需明确检查。不要仅用句号序号作为跨声音的缓存键。
- 若只反馈末句异常，保留已经认可的其他句子；可将修复句接到已认可的上下文后试听。
- 用户选定 A/B 后使用实际选中的文件，不重新生成一个“同参数”版本代替。
- 新音频重测时间，重新检查字幕、动作预算和观察保持。不默认拉伸音频来填旧时间。

## 验收记录

分别记录：生成后端和条件、参考录音/输出哈希、自动检查、用户反馈覆盖的片段、全片听音是否完成。缺少听音能力或反馈时直接说明这部分未验证，不从参数、声纹相似度、波形对齐或 ffprobe 推出“声音完全一致”。
