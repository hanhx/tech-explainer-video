# 封面、文案与章节整理

先确认当前成片版本，以及用户在改封面、标题、章节还是视频长度。上下文已能确定时直接完成；“总结成 5–7 章”归并章节，“压到 5–7 分钟”才涉及剪片。保留已有视频及字幕，除非用户要求修改。

## 封面让观众先认出主题

先定三层信息：**讲谁/什么主题 → 与观众有关的矛盾 → 来源或系列识别**。字号层级由用户优先级决定，不能为了留白把关键主题藏成小字。每张封面只保留一个主要矛盾，画面直接支撑它；长解释放简介。

- 用户要 Super Agent 大字、强调 DeepSeek Harness 文章时，保留这两个真实识别词；“AI 能并发，你能吗”可承接个人注意力的矛盾。不要只剩一个脱离主题的精致隐喻。
- 来源以“文章解读”等真实关系呈现；原型/架构文章不能包装成正式产品发布，来源名称不意味着官方背书。
- 只有系列前作与本片存在具体联系时才延续系列创意，不能为了 YES Engineer 等熟悉词硬转主题。
- 4:3、3:4 分别构图，不把横图直接裁成竖图。检查真实像素宽高比、边缘安全区、中文笔画与英文拼写；用实际缩略图尺寸看主题和矛盾能否迅速辨认。
- 调用生图/编辑工具前将实际提示词、比例和目标文件名写入工程；异步任务完成后保存输出及对应关系。不能只在临时变量里留提示词，最后交一份空记录。
- 用户反馈低点击率时，先区分已知数据与设计推测。没有曝光、受众、投放条件和对照结果，不能确定“太抽象”就是原因，更不能把新封面称为已提高 CTR。封面、标题、开头要兑现同一承诺。

## 文案可直接复制

按平台或用户给定的限制实测标题与简介字符数；采用包含空格、标点、英文字母、链接及话题的保守计数，并说明计数口径。平台实时规则未知时不编造“官方限制”。本次用户给出的标题 30 字、简介 1000 字是约束示例，不自动应用到其他平台。

简介先交代观看收益与内容，保留关键证据边界；背景音乐等许可要求的署名必须完整。话题使用正文真实涉及的品牌、主题与受众词，不冒充热搜排名。直接交付图片和可复制文字，只有用户要求才打 ZIP。

## 章节从当前成片定位

1. 读取当前 MP4 的真实总时长和配套 `actual-timeline.json`，核对二者版本；不要用旧稿预估时间码。
2. 按内容目标把**连续 cue**归并为用户要的章节数。记录每章首尾 cue、标题与首 cue 的实际起点；全部主要内容覆盖一次，不交错、不遗漏。
3. 以画面/旁白实际进入该章的时刻复核边界。需要便于提前定位时可向下取整到秒，明确该口径；不能整片按分钟均分。
4. 分别交付“发布用章节”和“视频已烧录标题”的事实，不把文案整理描述成重新渲染。新章节数不改变总时长。

Super-agent V18 的“5–7”曾被误解为压缩时长，实际是在 08:44.750 的成片上归并章节。迁移的是先判对象、再按实际时间归组的方法，不是固定七章或复用该时间码。
