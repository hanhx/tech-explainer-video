# 声音与节奏修复：先定位，再改处理

用于持续底噪、声音小/空灵、断句空白与相对倍速反馈。沿用已选音色和实际录音；不默认重新生成整片。DeepInfer案例是经验来源，不是通用DSP标准。

## 找到声音在哪一步变坏

对同一句比较：原始take → 逐句变速/降噪后 → 整段母带 → 最终AAC。记录版本、cue、文件哈希和处理顺序。用户说开头持续沙沙声时，先排查实际声音与新增环境轨；不能直接猜成BGM。只有原始take本身的异常才考虑整句重录。

|反馈|优先检查|修复方向与复核|
|---|---|---|
|声音小|人声有效段响度、峰值余量、整片母带与播放器增益|测量与试听分开。若尖峰限制增益，适量控制峰值后重新从未母带人声处理；不反复加loudnorm/限幅，也不以目标LUFS代替实测|
|空灵、金属或齿音不舒服|原始take是否正常；强降噪、硬门限、连续多次变速、EQ/压缩是否叠加|保留同一take，从原始PCM做更轻候选。先配平响度比较音色，再以实际音量试听；不能把“更响”误当“更自然”|
|持续底噪|噪声在有声/无声段的差异、原始与处理后差异|轻降噪与必要的柔和段间控制；检查起音、尾音和呼吸。降噪阈值不能从别的音轨直接套用|
|请求前像缺词或停很久|前句结束、前镜保持、当前take头部空白、字幕切点|完整回听前后句，先确定是否真的缺词。只裁异常空白，保留起音/尾音余量；自然停顿保留|

不要把某个afftdn噪底、压缩比、-14LUFS或atempo值推广为所有声音的默认。DeepInfer只对18.733秒B试听得到“更自然，音量合适”；整片技术校验不扩大此范围。该案例的处理链保存在案例工程内，未覆盖通用speech-mobile-v1和个人profile。

## 三个时钟分别控制

1. **讲述时钟**：实际语速、词间停顿与术语读法。
2. **动作时钟**：一个信息块移动、镜头重排或状态变化需要多久。
3. **观察时钟**：动作停稳后，观众读图和比较结果的时间。

用户要求“V6声音×1.5”时，先确认指音频相对版本还是播放器整体倍速。按源处理溯源计算总速率，例如原始take先×0.92再×1.5，等效×1.38；需要时从原始take单次处理达到目标。播放器×1.5会同时压缩动作与保持，不等于只提速配音。已经认可的未改句仍直接复用。

旁白变短后，重测时长，但不要把旧镜头整段等比压缩。按关键词触发状态与到达事件，为复杂图独立保留观察时间；时长采用max(实际音频,实际动作)+保持。动作应利落还是放缓，要依据反馈与预演，不能机械理解“画面变快”。固定旁白之外的动作不应继续依赖source_duration等旧时长比例。

## 量化异常空白

可先用标准库工具做只读筛查：

```sh
python3 "$SKILL/scripts/inspect_narration.py" "$PROJECT/out/final/actual-timeline.json" \
  --root "$PROJECT" --output "$PROJECT/checks/narration-gaps.json"
```

也支持build_timeline.py的scenes/cues结构。报告基于可配置RMS阈值（默认-38dBFS）与10ms窗口估计有效段，合并前句尾部、slot保持和后句头部，列出相邻有效段间隔。它不是VAD、词级对齐或漏词判断；弱辅音可能低于阈值，不自动裁切任何音频。明显异常的间隔再回到实际上下文核对。

修复时保存原始哈希、旧/新文件与裁切边界；先短上下文试听，再更新时间轴、字幕与事件。用户反馈的具体文件与范围单独记录，锁定文件不能被新处理就地覆盖。
