# 连续运动与动作声音

用于“像 PPT”“动画不丝滑”“只有叮声/沙沙声”等反馈。先定位当前版本的具体动作，再改动；不默认换画风、提速旁白或重录声音。叙事职责见 [storytelling.md](storytelling.md)，修订范围见 [production-discipline.md](production-discipline.md)。

## 让动作承担解释

同一对象保留稳定身份、方向、编号和去向。例如消息从原讨论进入处理者，结果回到交付处；画面的改变来自真实操作，而不是容器一起放大。主次用聚焦、局部变化、亮度与空间重排表达；不必每镜移动摄像机。

条件变化也必须进入时间轴。“正在输入”切换为“停止等待”、“已启动”切换为“完成”时，同步调整旁白/字幕与可见状态。切换策略不能顺手删除历史结果；为重演而清空场景时明确重置原因，避免暗示机制会撤销过去发生的事。

| 可见问题 | 优先修什么 |
|---|---|
| 每镜卡片淡入、整页推近 | 让数据、任务或引用完成一次有起点和终点的操作；镜头跟随关键对象 |
| 对象突然换位置/活跃窗口跳格 | 对同一对象的位置、尺寸和透明度连续插值；整数索引仅决定目标，不直接决定显示位置 |
| 前后画面能看，中间穿帮 | 检查遮挡层级、标签退出与新对象进入的顺序；关键标签先稳定可读再离场 |
| 进度/表针到头突然弹回 | 循环只用于确实循环的对象；任务完成保留终态，需要重置时演出重置原因 |
| 所有转场都做形变 | 只对身份相同的对象形变；逻辑视图换部署视图要有明确关系，不能暗示两个实体相等 |
| 60 fps 仍显得卡 | 查坐标、分支、纹理/字形重建与时间采样突变；重复帧或补帧不能修复源状态跳变 |

帧率由画面运动和交付需要决定；必要时原生重绘 50/60 fps，保留总时长与旁白。细字/线条抖动可先检查亚像素取整与缩放重采样。缓动只处理速度曲线，不修正错误的状态顺序。

## 声音也有动作分工

旁白、BGM、状态提示、运动音/拟音分开维护，最终再混。先定义一个小而统一的音色组，按听感扩充；不要用固定种数代替设计，也不要所有动作都响。

| 声音层 | 绑定事件 | 注意 |
|---|---|---|
| 运动音 | 展开、聚拢、滑入、飞行的起步与加速 | whoosh/zip 的长度跟随动作；避开持续白噪声，收尾可另接轻落点 |
| 落点/状态 | 到达、接纳、冲突、完成 | 到达时才响；“已启动”不能配“已成功”的声音 |
| 鼠标 | 可见按下与松开 | 点击声不是指针经过每个图标都响；双击应有真实两次点击 |
| 键盘 | 字符或输入事件 | 适量抽取节奏，不逐字覆盖人声，不用鼠标声伪装输入 |
| 表盘 | 指针跨刻度或等待脉冲 | 从同一运动时钟生成 tick/tock；任务完成就停，重置与暂停要对应画面 |

分镜中的“声音”列直接记录 `对象/动作、事件时点、音色、增益、停止条件`，无需另造审批表。同一群对象一起移动通常只配一层声，避免逐对象累加。音效不携带画面尚未发生的成功含义。

`scripts/action_sounds.py` 提供原创合成的 `motion_swish`、`motion_sweep`、`motion_land`、`mouse_down`、`mouse_up`、`mouse_click`、`keyboard_tap`、`clock_tick`、`clock_tock`。使用 NumPy 和固定种子，不依赖网络音效库；它们是起始音色，最终音量与质感仍需试听。Pillow 引擎可直接用名称，旧音效名称保持原行为。

```python
# 在 draw_* 内无条件登记事件；引擎收集时只调用这一镜的 t=0。
start = ctx.at('送过去')
arrival = start + travel_duration
ctx.sfx(start, 'motion_swish', 0.65)
ctx.sfx(arrival, 'motion_land', 0.5)
# 画面与声音共同使用 start / arrival，而不是复制两套时间值。
```

需要试听素材时：

```sh
"$PY" "$SKILL/scripts/action_sounds.py" --out "$PROJECT/sfx" \
  --kinds motion_swish mouse_click clock_tick clock_tock
```

该脚本只生成 WAV。引擎先查项目 `sfx/`，再查 Skill 音效资产，最后合成；不要假设一个未被引擎读取的目录会自动生效。每次实际混音检查余量、人声可懂度与尾音，不拿 synth 的峰值当最终成片响度。

可运行源码样段见 `assets/examples/debounce-actions-v1/`，使用同一事件表驱动画面与声音。它是无配音的专项预演，不是有声成片模板；验证范围与复现命令见 [0.3.1 验证记录](evaluation-v0.3.1.md)。

## 验证运动与同步

1. **先短预演**：选最容易暴露问题的连续段，包含对象重排、动作密集处、语音及保持。只改声音时沿用画面，先做混音短样。
2. **看编码后的过程**：从实际 MP4 抽转场前、中、后及邻近帧；快速动作按其长度加密到逐帧检查。查看对象轨迹、层级遮挡、字幕切换与终态，再正常速度连续播放。
3. **去文字看操作**：隐藏解释文字，检查动作是否仍表达输入、变化与结果。接触表适合构图与语义，不能证明速度曲线、声音或丝滑程度。
   `--at-events` 依据声音事件后 0.5 秒抽帧，只是启发式；新增点击/刻度音可能挤掉关键视觉状态。需要展示“变化前→触发→变化后”时，可在 cue 中写 `review_times_s: [9.9, 10.0, 10.2]`（实际绝对秒，数量与 `--points` 列数一致）。接触表优先使用这些时点并校验边界，不把采样没拍到当成动作不存在。
4. **听动作与人声**：耳机和目标观看设备分别试听；移动/点击/刻度与可见事件一致、没有抢词、反复底噪或尾音叠加。数字检查可发现峰值、时间偏移、声道异常，不能代替听感。
5. **保存范围**：记录文件哈希、实际检查的时段、静帧/连续播放/试听分别做了什么。未连续播放或未人工听完要如实写明，不把脚本帧差通过升级为“整片丝滑”。

## 本次经验的边界

Super-agent V17 获得“这次非常完善了”的整体反馈，随后用户提出运动音、鼠标声和表盘声需求；V18 加入这些声音并复用原画面。它支持“按动作补声音”的方法，不证明新增混音已获全片人工听音通过。60 fps、具体增益、纸感配色和双单声道是项目选择，均不是通用默认。
