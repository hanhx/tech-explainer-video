# 连续运动与动作声音

用于“像 PPT”“动画不丝滑”“只有叮声/沙沙声”等反馈。先定位当前版本的具体动作，再改动；不默认换画风、提速旁白或重录声音。叙事职责见 [storytelling.md](storytelling.md)，修订范围见 [production-discipline.md](production-discipline.md)。

## 让动作承担解释

同一对象保留稳定身份、方向、编号和去向。例如消息从原讨论进入处理者，结果回到交付处；画面的改变来自真实操作，而不是容器一起放大。主次用聚焦、局部变化、亮度与空间重排表达；不必每镜移动摄像机。

条件变化也必须进入时间轴。“正在输入”切换为“停止等待”、“已启动”切换为“完成”时，同步调整旁白/字幕与可见状态。切换策略不能顺手删除历史结果；为重演而清空场景时明确重置原因，避免暗示机制会撤销过去发生的事。

用可见的局部动作演出结果何时成立。接下一镜时带上同一对象的编号、已完成状态和仍待处理的信息；进出镜或剪掉实录等待时间后，核对相邻镜的初末状态。画面落点与声音使用同一锚点，音量和尾音随所剪片段复核。

| 可见问题 | 优先修什么 |
|---|---|
| 每镜卡片淡入、整页推近 | 让数据、任务或引用完成一次有起点和终点的操作；镜头跟随关键对象 |
| 对象突然换位置/活跃窗口跳格 | 对同一对象的位置、尺寸和透明度连续插值；整数索引仅决定目标，不直接决定显示位置 |
| 前后画面能看，中间穿帮 | 检查遮挡层级、标签退出与新对象进入的顺序；关键标签先稳定可读再离场 |
| 进度/表针到头突然弹回 | 循环只用于确实循环的对象；任务完成保留终态，需要重置时演出重置原因 |
| 所有转场都做形变 | 只对身份相同的对象形变；逻辑视图换部署视图要有明确关系，不能暗示两个实体相等 |
| 60 fps 仍显得卡 | 查坐标、分支、纹理/字形重建与时间采样突变；重复帧或补帧不能修复源状态跳变 |

帧率由画面运动和交付需要决定；必要时原生重绘 50/60 fps，保留总时长与旁白。细字/线条抖动可先检查亚像素取整与缩放重采样。缓动只处理速度曲线，不修正错误的状态顺序。

相邻素材推进不顺时，对照源素材出入点以及最终编码的上一镜末帧、下一镜首帧和附近帧，核对编号、位置、输入、计数和结果。记录选择的源时间码，保留能证明状态变化的连续片段。检查重复帧、跳帧和剪辑点，再按动作需要决定采样与帧率。

## 声音也有动作分工

旁白、BGM、状态提示、运动音/拟音分开维护，最终再混。先定义一个小而统一的音色组，按听感扩充；不要用固定种数代替设计，也不要所有动作都响。

| 声音层 | 绑定事件 | 注意 |
|---|---|---|
| 运动音 | 展开、聚拢、滑入、飞行的起步与加速 | whoosh/zip 的长度跟随动作；避开持续白噪声，收尾可另接轻落点 |
| 落点/状态 | 到达、接纳、冲突、完成 | 到达时才响；“已启动”不能配“已成功”的声音 |
| 鼠标 | 可见按下与松开 | 点击声不是指针经过每个图标都响；双击应有真实两次点击 |
| 键盘 | 字符或输入事件 | 适量抽取节奏，不逐字覆盖人声，不用鼠标声伪装输入 |
| 表盘 | 指针跨刻度或等待脉冲 | 从同一运动时钟生成 tick/tock；任务完成就停，重置与暂停要对应画面 |

分镜中的“声音”列直接记录 `对象/动作、事件时点、音色、增益、停止条件`，无需另造审批表。同一群对象一起移动通常只配一层声，避免逐对象累加。音效不携带画面尚未发生的成功含义。

先判断现在最需要观众察觉什么。按下、到位、确认等短事件把瞬态对齐到对应画面。跨区移动用跟随动作的短音，逐步累积用能随进度发展的声音。镜头仅换角度、背景持续移动、相同动作高频重复，或旁白正在讲关键条件时，优先留白。同一动作兼有移动和落点时，先突出决定结果的那个时刻，再决定是否需要补运动音。

`scripts/action_sounds.py` 提供原创合成的 `motion_swish`、`motion_sweep`、`motion_land`、`mouse_down`、`mouse_up`、`mouse_click`、`keyboard_tap`、`clock_tick`、`clock_tock`。使用 NumPy 和固定种子，不依赖网络音效库；它们是起始音色，最终音量与质感仍需试听。Pillow 引擎可直接用名称，旧音效名称保持原行为。

```python
# 在 draw_* 内无条件登记事件；引擎收集时只调用这一镜的 t=0。
start = ctx.at('送过去')
arrival = start + travel_duration
ctx.sfx(start, 'motion_swish', 0.65)
ctx.sfx(arrival, 'motion_land', 0.5)
# 画面与声音共同使用 start / arrival，而不是复制两套时间值。
```

需要试听素材时：

```sh
"$PY" "$SKILL/scripts/action_sounds.py" --out "$PROJECT/sfx" \
  --kinds motion_swish mouse_click clock_tick clock_tock
```

该脚本只生成 WAV。引擎先查项目 `sfx/`，再查 Skill 音效资产，最后合成；不要假设一个未被引擎读取的目录会自动生效。每次实际混音检查余量、人声可懂度与尾音，不拿 synth 的峰值当最终成片响度。

可运行源码样段见 `assets/examples/debounce-actions-v1/`，使用同一事件表驱动画面与声音。它是无配音的专项预演，不是有声成片模板；验证范围与复现命令见 [0.3.1 验证记录](evaluation-v0.3.1.md)。

## 可商用的外部音效

先选这一镜该听到的动作，再按画面材质试听。手绘可以用纸张摩擦，3D 或机械镜头可以用扣合和轻碰，屏幕操作用实录键盘或短提示。起步、移动、到达可分配不同声音；让最关键的结果最清楚，旁白下面的移动声和空间声压低。抽象背景的漂移通常静音。

| 用途 | 可以试听的来源 | 许可 |
|---|---|---|
| 点击、按钮、确认 | [Kenney Interface Sounds](https://kenney.nl/assets/interface-sounds) | CC0 |
| 碰撞、落位 | [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds) | CC0 |
| 键盘、翻纸、扣合 | Freesound 的 [MacBook 键盘](https://freesound.org/people/khenshom/sounds/565645/)、[翻页](https://freesound.org/people/OwlStorm/sounds/151220/)、[门闩](https://freesound.org/people/xkeril/sounds/815491/) | 所列单条为 CC0 |
| 短提示、接受与拒绝 | [Lokif GUI Sound Effects](https://opengameart.org/content/gui-sound-effects)、[Fupi 的 8-bit 短提示](https://opengameart.org/content/8bit-menu-highlight) | CC0 |
| 推镜、扫过、跨屏移动 | [Mixkit Whoosh](https://mixkit.co/free-sound-effects/whoosh/) | 使用页面标为 Sound Effects Free License 的条目 |

- [CC0](https://creativecommons.org/publicdomain/zero/1.0/) 音效可免费商用、剪辑和再分发，无强制署名。[Kenney 官方说明](https://kenney.nl/support)确认其素材页为 CC0。Freesound 和 OpenGameArt 逐条核对，表中条目的许可不能推到整个网站。

- 在当前项目记录实际使用的条目、作者、来源链接、许可和取得日期。保留原始文件与试听工作文件的对应关系，工程打包时按素材许可筛选。

### 剪映音色参考

以下四条是用户在剪映专业版确认喜欢的音色，作者均显示为「剪映小助手」。在「音频 → 音效库」按原名搜索。把音色与动作一一绑定，适用于像素、手绘、扁平及其他动画。

| 剪映原名 | 适合的动作 | 找可复用替代时听什么 |
|---|---|---|
| 啵1 | 关键词、图标或小物件弹出来 | 短、圆、有一点弹性，出现那一帧响 |
| 仙尘音效 | 关键线索亮起来、揭晓、变身或结果逐步显现 | 细碎亮音铺开，有自然尾音，跟显现过程一起走 |
| 任务完成 | 校验完成、结果确认、一个任务真正结束 | 有明确收束的短提示，放在结果成立的时刻 |
| 唰 | 对象划过、推拉镜头、擦拭转场 | 短气流跟随运动，长度按动作剪 |

商用时开启「商用」筛选并看具体条目的授权、平台和费用。2026-11-09 在本机专业版，以上四个原名均可在热门列表看到，商用筛选下逐条搜索未返回可商用素材。本 Skill 保留名字和声音设计参考。用于可分发工程时，从上表的开放许可来源选同类音色，或用有明确授权的自制音效。剪映素材的使用范围按[剪映素材使用许可协议](https://sf1-cdn-tos.douyinstatic.com/obj/ies-hotsoon-draft/vco/f72e9cd9-cc19-4db7-ba74-0794833ce854.html)及产品当时显示的条款核对。

## 项目内音效

优先试听本期项目已有的音效。Pillow 的项目音效放在项目根目录下的 `sfx/`。素材清单用项目相对路径，例如 `sfx/card_seat.wav`，并记录来源与许可。用户提供的原始 MP3 或试听合集可按镜头需求选取片段，转成单条 WAV 后导入项目。

| 可见事件 | 可试听的音色 | 摆放时点 |
| --- | --- | --- |
| 对象明显跨区、快速扫开或入场 | 短扫过声 | 对齐运动起步或加速段。尾音长时按动作长度收短 |
| 卡片入槽、物体接触或关键对象弹出 | 短促闷弹、带低频尾音的撞击 | 主瞬态对齐接触或弹出的那一帧。轻动作先试短音，强调重量时试听低频尾音 |
| 按钮按下、双击或有意义的一组离散事件 | 单次轻敲、双击或连击 | 对齐可见输入或刻度。多次脉冲的间距要与画面节奏吻合 |
| 进度递增、信号升高或揭晓前逐步聚焦 | 阶梯式或连续上扬 | 在变化开始时进入，随增长推进，关键结果出现时收束 |
| 关键结果显现或校验完成 | 短提示音或带亮尾的叠音 | 在结果实际成立时进入，给尾音留出空间 |
| 频率、能量或对象状态发生可见弯折 | 音高弯折 | 将音高变化与状态轨迹同步，先确认音色适合该场景 |

按实际起音或主瞬态对齐画面。WAV 有前导时可提前摆放或先裁前导。局部试听要带上相邻旁白，听清关键词和动作先后再定增益。项目缺少合适音效时，先试内置合成音色，或按缺口找授权素材。

### 接进 Pillow 或剪辑工程

试听后把选中的片段转成 WAV，放到 `$PROJECT/sfx/`。文件名与动作事件一致。新名字可与内置音效并用；若用同名 WAV 替换已有音效，项目文件优先，沿用现有时点。Pillow 的混音会叠加这些片段，录音偏长时先剪取动作附近，再在成片里核对起音和尾音。

```sh
mkdir -p "$PROJECT/sfx"
ffmpeg -n -i "$INPUT" -ac 1 -ar 48000 -c:a pcm_s16le "$PROJECT/sfx/card_seat.wav"
```

在 `draw_*` 中无条件登记 `ctx.sfx(arrival, 'card_seat', 0.5)`，`arrival` 同时用于画面落点。其他引擎或剪辑器也用这个可见时点摆放 WAV。先做一小段正常语速试听，比较音效是否遮词，核对手机扬声器上是否听得清。记录的增益和音效选择只服务于当前片段。

## 验证运动与同步

1. **先短预演**：选最容易暴露问题的连续段，包含对象重排、动作密集处、语音及保持。只改声音时沿用画面，先做混音短样。
2. **看编码后的过程**：从实际 MP4 抽转场前、中、后及邻近帧；快速动作按其长度加密到逐帧检查。查看对象轨迹、层级遮挡、字幕切换与终态，再正常速度连续播放。
3. **去文字看操作**：隐藏解释文字，检查动作是否仍表达输入、变化与结果。接触表适合构图与语义，不能证明速度曲线、声音或丝滑程度。
   `--at-events` 依据声音事件后 0.5 秒抽帧，只是启发式；新增点击/刻度音可能挤掉关键视觉状态。需要展示“变化前→触发→变化后”时，可在 cue 中写 `review_times_s: [9.9, 10.0, 10.2]`（实际绝对秒，数量与 `--points` 列数一致）。接触表优先使用这些时点并校验边界，不把采样没拍到当成动作不存在。
4. **听动作与人声**：耳机和目标观看设备分别试听；移动/点击/刻度与可见事件一致、没有抢词、反复底噪或尾音叠加。数字检查可发现峰值、时间偏移、声道异常，不能代替听感。
5. **保存范围**：记录文件哈希、实际检查的时段、静帧/连续播放/试听分别做了什么。未连续播放或未人工听完要如实写明，不把脚本帧差通过升级为“整片丝滑”。

## 本次经验的边界

Super-agent V17 获得“这次非常完善了”的整体反馈，随后用户提出运动音、鼠标声和表盘声需求；V18 加入这些声音并复用原画面。它支持“按动作补声音”的方法，不证明新增混音已获全片人工听音通过。60 fps、具体增益、纸感配色和双单声道是项目选择，均不是通用默认。
