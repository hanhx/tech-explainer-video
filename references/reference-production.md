# 按认可样例制作：可执行基础与效果对照

用户希望稳定产出接近这支联网科普片的效果。该参考用于指导 Agent 制作，不依赖打开抖音、看封面截图或凭成片印象猜实现。当前已选的表现方式应作为制作起点，不再每次从空白工程重选风格。

## 实际材料

- `assets/examples/wifi-protocols-v6/project/`：该次最终 renderer、项目数据、词时点、必要工具；本机另保留实际选中的 26 段 WAV。Git 仓库排除视频和音频，源码版仍能克隆和校准画面。
- `assets/examples/wifi-protocols-v6/goldens/`：从原工程生成的 4 张完整尺寸基准帧及哈希，覆盖 MAC 特写、DHCP 时间回放、ARP 通道、五层剖面。
- `assets/handdrawn-kit/visuals.py`：从已交付工程提取的绘图、字体缓存、颜色、字段卡片、局部高亮、报文位移组件，不依赖原工程 shots.json。新题目可复用其绘制基础，替换对象和场景。
- `assets/handdrawn-kit/profile.json`：本片的画幅、颜色、字号、舞台/状态区/字幕区和运动特征。它是选用本样例时的起始样式约定；改画幅或主题需要重排，不直接拉伸。
- [参考案例](example-wifi-protocols.md)：成片、动态选段、分镜与返工经验。

不含个人参考录音、模型、本机语音配置或缓存。已有 WAV 仅用于复现该片；新内容按当前用户/工程声音条件生成，不能拿旧旁白充当新讲稿。

## 先证明基础可以复现

在新的可写工作目录执行，不在 Skill 资产目录渲染：

```sh
python3 "$SKILL/scripts/reference_project.py" clone "$WORK/reference-calibration"
python3 "$SKILL/scripts/reference_project.py" check "$WORK/reference-calibration" --python "$PY"
```

`$PY` 为已有 Pillow/NumPy 环境；视觉校准不需要配音、视频或 TTS 模型。本地已有配音时，重建有声视频还需 FFmpeg/ffprobe，不需 Manim 或语音模型。默认字体使用 macOS Hiragino Sans GB/Menlo；其他平台通过 `EXPLAINER_FONT`、`EXPLAINER_MONO_FONT` 指向合法可用字体。

check 对未修改克隆生成真实帧，与原始基准比较。相同环境下可精确比对；字体或渲染依赖不同会导致差异，需要对照确认，不能直接把新环境当成已经校准。新题目改完后不再要求画面逐像素等于网络片，避免把正确的新内容当作错误。

完整有声复现需要本机保存的配音，路径与哈希见 project-manifest.json；Git 克隆默认没有这些文件，脚本会列出缺失项，不伪造声音。新任务使用自己的实际配音并更新词时点/时间轴。媒体不自动下载，也不随 git push 上传。

完整复现命令（本地配音齐全时，在克隆目录中）：

```sh
python3 tools/build_timeline.py project.json
python3 scene.py --draft
python3 scene.py --final
python3 tools/verify_video.py out/final/video.mp4 --timeline out/final/actual-timeline.json --align-audio --output out/final/verification.json
```

示例数据从 `project.json` 驱动语音与时长，`shots.json` 驱动画面文案，`calm.py` 绑定该片具体机制；这些不是可只换标题的通用内容模板。源工程已有分段缓存，但其全局源文件依赖会扩大失效范围；不宣称已经支持任意主题的精确增量渲染。

## 新题目怎样延续效果

1. 先写新机制的因果链、持续存在的对象、状态账本和分镜。保留“跟同一对象完成流程 → 明确回看局部 → 反例/恢复 → 收束”等适用叙事方法，不照抄协议顺序、设备名称或历史对照。
2. 对流程/状态/字段型科普，优先在已验证的过程绘制基础上重写场景，复用 `visuals.py` 的组件。新主题若确有数学、三维或界面需求，可按引擎选择规则换引擎，同时落实所选参考的视觉约定；用户本轮指定优先。
3. 延续这套颜色、字体层级、固定信息区、稳定纹理与克制的运动。新对象用统一的绘制方法创建，长值自动换行或重排，避免散落的临时字号/坐标补丁。
4. 新片先做一个包含关键机制、密集标签和状态更新的实际配音短段。输出“参考帧/新片帧/具体差异”对照：画面层级、对象连续性、动作是否表达机制、字段是否可读、声音术语、结果是否在事件之后出现。发现差距就在短段修复，达到所选参考方向再扩展全片；已有清楚选择不反复索取确认。
5. 用实际几何执行容器/避让检查，再看动态过程。成片做最终编码帧复查、完整解码和源音频对齐。对照记录可验证一致性与具体问题，不虚构一个能自动代表审美、学习效果或听感的总分。

## 已选样式的检查约定

| 维度 | 延续的表现 | 应阻止进入全片制作的问题 |
|---|---|---|
| 视觉 | 浅纸色、稳定细笔线、语义配色、明确标题/世界/状态/字幕层级 | 字段出所属容器，标签和值相交，设备残片或无意义线路越框 |
| 叙事 | 同一对象/数据可追踪，回放和当前过程明确 | 每镜重置对象、状态提前出现、局部拆解被看成重新执行 |
| 动作 | 报文、字段、界面和状态承担解释；重要动作后能观察 | 运动经过待读文字，多焦点抢视线，定义静止被误当漏动画而乱加运动 |
| 声音 | 常用缩写与中文名对应，术语读法和上下句连贯 | 把所有大写词机械拆字母；用 ASR 或参数代替试听 |
| 工程 | 沿用可运行基础，固定实际声音/依赖与版本 | 重新手写同类绘图功能、修改选中音频、套用旧成功报告 |

这种基础、组件、约定和对照流程能减少漂移与返工；不保证任意新题目一次生成就达到相同创作质量。真实新主题仍须验证机制与观看效果。
