# 画面风格

风格服务于讲解目标，不是装饰。先按受众和内容选一种主风格，全片统一；用户指定风格时直接采用。可以给用户 2–3 个候选并各出一帧静态样张，再选定。

## 选择

| 风格 | 适合 | 不适合 | 关键视觉 |
|---|---|---|---|
| 扁平示意 / 时序图 | 协议交互、请求流、架构；工程师受众 | 零基础、追求趣味的短视频 | 深或浅纯色底，统一圆角卡片，2–4 种语义色，细网格 |
| 卡通角色对话 | 把两方交互拟人（客户端/服务器、生产者/消费者）；大众受众 | 多于 3 个主体、需要精确数值的机制 | 圆润角色、表情与动作、对话气泡、多角色配音 |
| 贴纸 / 手账 | 轻松科普、清单式总结、社交平台 | 严肃文档、密集图表 | 白描边+投影、轻微旋转、弹出回弹、胶带、纸纹底 |
| 白板手绘 | 推导、"边画边讲"、概念从无到有 | 大量文字或快速切换 | 白底、`Create` 描线、手写感字体、单色+强调色 |
| 像素 / 复古游戏 | 系列化、关卡式（"STAGE 1 全表扫描"）；年轻受众 | 曲线、精细几何 | 低分辨率网格对齐、点阵字、限色板、关卡/HP/计数器 HUD |
| 终端 / 黑客 | 命令、日志、抓包、真实输出 | 抽象概念、非技术受众 | 黑底绿/琥珀字、等宽字体、光标、扫描线 |
| 3Blue1Brown 式几何 | 算法、数学、向量、矩阵、概率 | 系统组件与运维流程 | 深底、`MathTex`、`Transform` 连续变形、坐标系 |
| 等距 3D / 机房 | 部署拓扑、网络分层、数据中心 | 时序细节 | 等距投影方块、分层堆叠、`ThreeDScene` 或手算投影 |
| 信息图 / 数据新闻 | 对比、规模、比例（"3 次 IO vs 100 万次"） | 过程机制 | 大数字、条形/单位图、强对比、少量注释 |
| 隐喻场景 | 难以直接画的抽象（快递=数据包、图书目录=索引） | 隐喻会误导边界时 | 生活场景元素 + 明确标注"这只是比喻"的转场 |

组合原则：一个主风格 + 至多一种辅助手法（例如扁平示意里插入一次隐喻场景）。隐喻必须在片中回到真实机制，并说明它在哪里不成立。

## 像素风细分与中文可读性

像素风不是一种风格。选定子类后，调色板、分辨率、字体、动效都跟着定：

| 子类 | 画布（16:9） | 调色板 | 适合 |
|---|---|---|---|
| 1-bit | 480×270 | 2 色 + 网点抖动 | 极简概念、黑客感 |
| Game Boy | 320×180 | 4 阶绿 | 怀旧短系列 |
| 8-bit（FC/NES） | 320×180 | NES 54 色中每画面取少量 | 关卡式、轻量信息 |
| 16-bit（SFC/MD） | 480×270 | 16–32 色，抖动渐变，多层视差 | 有场景与角色的叙事科普（推荐给中文多的视频） |
| PICO-8 | 480×270（原生 128² 不适合中文） | 固定 PICO-8 16 色 | 系列视频统一风格 |
| 街机 / CRT | 任意 + 扫描线、暗角 | 高饱和 | 片头、高潮镜头 |
| PC-98 点阵 | 640×360 | 16 色 + 精细抖动 | 氛围、偏文艺 |
| 等距像素 | 480×270 | 16–32 色 | 架构、机房、拓扑 |
| 现代高清像素 | 像素角色 + 高清光影/粒子 | 自由 | 信息量大、兼顾清晰度 |

**中文文字的硬规则**（违反就会糊）：
- 用**专门的中文点阵字体**，并按其设计尺寸的整数倍使用：Fusion Pixel / Ark Pixel（TakWolf，OFL，10/12/16px）、Zpix（12px）、GNU Unifont（16px）。不要把黑体、苹方等矢量字体缩到 12px 再关抗锯齿——多笔画字会粘连断笔。
- 关闭抗锯齿（PIL `d.fontmode = "1"`），先在低分辨率画布上绘制，最后**整数倍 NEAREST 放大**（480×270 ×4 → 1920×1080）。非整数缩放会产生粗细不均的像素。
- 正文 12px（放大后 48px 物理像素），标题用 24/36px（12 的整数倍）。一行不超过约 30 个汉字。
- 字体许可证（OFL）随工程保存；字体文件不进通用 Skill 模板，按需下载到项目 `fonts/`。
- 若必须用矢量字体（字库缺字），改为“像素画面 + 高清字幕层”分层渲染，而不是硬缩矢量字。

**像素风其他要点**：限定调色板（如 Sweetie 16、PICO-8、Endesga 32）全片只用这些颜色；渐变用 Bayer 抖动而非平滑渐变；运动按整数像素步进；转场用抖动溶解、马赛克或卷帘；UI 用 RPG 文本框（逐字打出 + 闪烁箭头）、HUD 计数器、STAGE 标题；音乐用方波/三角波/噪声的芯片音乐。实现上 PIL 逐帧绘制最直接（见“何时不用 Manim”）。

## 在 Manim 中实现

- **卡通角色**：角色做成 `VGroup` 子类（身体 `Ellipse`、眼睛、嘴、手），提供 `blink()`、`talk(amp)`、`set_mood()`；嘴型用 updater 读取当前 cue 音频的 RMS 包络（numpy 预先按帧计算）。气泡用 `RoundedRectangle` + 三角尾，文字用 `AddTextLetterByLetter`。
- **贴纸**：对每个元素 `copy()` 一份 `set_stroke(WHITE, width=12, background=True)` 作白边，再加一份偏移、半透明深色副本作投影；入场用 `GrowFromCenter` + `rate_func=rush_from` 或自定义 back-ease 回弹，轻微 `rotate`。纸纹底可用 `ImageMobject`。
- **白板**：`Create` / `DrawBorderThenFill` 依次描线；线宽稍粗，`stroke` 带少量抖动（`apply_function` 加小噪声）；可选手写体（`MANIM_FONT` 指定）。
- **像素**：在 Manim 中坐标对齐网格并只用 `Square`/`Rectangle` 拼图；更简单的做法是 PIL 低分辨率逐帧绘制后 `NEAREST` 放大（见下文"何时不用 Manim"）。
- **终端**：`Code`/`Paragraph` 等宽字体，逐行 `AddTextLetterByLetter`，光标为闪烁 `Rectangle`。
- **3D/等距**：`ThreeDScene` + `set_camera_orientation`；或在 2D 中用等距投影手算多边形，渲染更快。

通用：颜色语义全片固定（例如客户端蓝、服务器橙、错误红、成功绿）；字幕层与世界坐标分离；转场（圆形遮罩、纸片扫过）只用于章节切换。

## 音乐与音效

- BGM 可选：在 project.json 写 `music.file`（相对路径）、`gain_db`（默认 -22）、`duck`（默认 true）。`render_project.py --mode final` 会循环、压低并在旁白时侧链闪避，最后统一响度。BGM 需用户提供或确认版权。
- 音效（数据包到达、成功、错误）用 Manim `self.add_sound(path, gain=-12)` 在动作的语义节点触发，不要每个动作都加。
- 音乐与音效不能替代听感验收；仍需用户实际听过。

## 何时不用 Manim

Manim 擅长几何、连续变形和可控时间轴。以下情况可以用 Python + PIL/numpy 逐帧绘制、通过 ffmpeg 管道编码（每帧 `rgb24` 写入 `ffmpeg -f rawvideo -i -`）：像素风、大量贴纸/位图合成、需要逐帧的角色口型和粒子。代价是没有 Manim 的对象/动画抽象，时间轴需自己维护。用户指定 Manim 时仍用 Manim；不擅自切换引擎。
