# 减少返工：局部修改、提前检查与发布

用于已有片的修订、长片或多次生成的工程。简单任务按需要采用，不增加重复的用户确认，也不把本项目的 2 秒、26 镜、五层网络或少箭头偏好变成所有题材的规定。

## 1. 先按修改范围决定重做什么

| 变化 | 应更新 | 通常可以保留 |
|---|---|---|
| 仅封面/发布文案 | 对应图片、文案与发布包 | 视频、配音、时间轴 |
| 标签、位置、报文路径 | 受影响镜头与共用组件实例；局部预演 | 配音；未变镜头的画面缓存 |
| 一句读音、重复或杂音 | 该 cue 的候选音频、实际词时点和局部预演 | 其他实际选中的 WAV；不换整片音色 |
| WAV 时长或动作预算 | 该镜画面与事件时点、后续绝对起点、字幕/章节 | 以局部时间实现且内容/时长未变的后续镜头画面 |
| 剧本/因果或状态设定 | 先改分镜与状态账本，再处理受影响声音、画面 | 已独立确认且不受影响的素材 |

先列受影响 cue/共享组件与输出，不先启动整片高清。用户报时间码时先明确是哪个版本，将时间映射到稳定 cue id；修改后时间码会漂移。共用组件修复后检查它在相关镜头里的实例，而不只检查报错那一帧。

## 2. 尽早暴露高风险问题

在昂贵的整片渲染前，集中看最拥挤、最大字段、动态经过标签、镜头推拉和状态刚更新的画面。用短的实际配音动态片段排错；范围和长度按问题决定。静态布局正确仍要看移动过程。

- 用实际字体度量文字，检查标签和值之间的间距，以及文字在其所属卡片/设备内的边距；只检查画布边缘会漏掉“在画布里却已经出卡片”的问题。
- 导出镜头/物体移动后的同一坐标系矩形，检查重要文字与运动通道。不要把移动报文、指引线、连线安排在待阅读的字段上。
- 分镜记录初态、触发事件、终态与跨镜保留状态。填写配置、画出网页等结果要在相关事件之后。历史对照、回放与当前过程要给清楚的切换依据。
- 箭头、运动和高亮按叙事需要使用；需要读定义、参数或对比时允许静止。近静止扫描只筛查漏编动作，不用无意义运动填满统计。

`scripts/check_layout.py` 可检查渲染器导出的 `layout-samples.json`：

```sh
python3 "$SKILL/scripts/check_layout.py" "$PROJECT/layout-samples.json" \
  --output "$PROJECT/checks/layout-preflight.json"
```

输入 `frames` 中每项给 `scene_id`、实际 `time_s`、`viewport` 和 `elements`。矩形统一为 `[x,y,width,height]`。元素以 `parent` 绑定容器，容器可写 `padding`；`avoid_overlap` 明确列出不应相交的 id 对。模块注释有最小结构示例。为运动过程采样开始、途中、结束及语义事件前后；相机转换后才导出。

该脚本不自动提取任意 Manim/Pillow/Remotion 的文字，也不理解哪些叠放有意。渲染器需接入一次几何导出；没有接入的片不能宣称已经通过此检查。矩形只是筛查，实际字体、遮挡、手机可读性与因果仍需动态复查。

## 3. 术语在长段生成前处理

先整理当前题目的缩写、中文名和希望的读法，并用包含术语的自然短句试听。比如本次用户选择 MAC 地址连读，不能据此让所有大写词都逐字母朗读，也不把这一读法强加给其他用户。

可在 `project.json` 配置项目级字面映射：

```json
{"pronunciations": {"MAC": "麦克", "TCP": "T C P"}}
```

只有 cue 没有显式 `tts_text` 时应用映射；`MAC地址` 可以得到连续的 `麦克地址`，而 `IP` 不会误改 `IPv4` 内部。正式 `spoken_text`、字幕与画面文字保持规范形式。映射只改变送 TTS 的文本，并进入现有文本缓存键；不改本机声音默认。

已有实际 WAV 的复用、cue 的 `--only` 和锁定规则继续适用。首次成功运行会把实际使用的默认 seed 写回对应 cue，后面插入/重排分镜时不因位置变化导致这些 cue 换种子。旧工程已有显式 seed 的不改。

遇到发音、卡顿或杂音，先定位原始 cue 与混音/编码版本，分清生成异常和后处理异常。给少量代表片段及清楚的旧/新顺序，不把 ASR 或文件参数当听感结论。实际选定文件直接复用，不再用“相同参数”重新生成一次。

## 4. 复用缓存并隔离任务

TTS 中断后，`synthesize.py` 会复用匹配文本/声音/seed 文件名下完整的 `.local/tts-raw/*.wav`，只补缺失的原始音频，再各处理一次。非法/截断原始文件会报具体 cue 并保留，不静默覆盖；`--dry-run` 显示 generate、process raw、cached。

Manim 项目在检查了输入依赖后，可加 `render_project.py --cache`，使用项目 `.local/manim-cache/` 下的持久原生 play 缓存。默认完整渲染行为不变；不加该选项可避开疑似旧缓存。缓存命中不等于声音、实际时间轴或最终合成已验收。

自定义渲染器应按镜头缓存静音画面：键包含该镜的局部数据、实际依赖、分辨率/帧率与渲染器版本；词时点变化属于画面依赖。不要只因后续镜头绝对起点改变而把相同局部画面作废；共用组件变化应使它的使用者失效。单个大全局文件的哈希会让所有镜头一起失效，可在适合时拆出分镜数据和实现。未追踪的依赖不能假定不影响画面。

每个任务使用独立的混音 WAV、临时 MP4、清单与报告路径；并发预演和正式渲染不能共用一个 `narration.wav`。`render_project.py` 的合成临时视频放在独立 run 目录。同一发布目录应只有一个写入者。不要在正在渲染时继续改它的源码/时间数据；新修改进入下一次任务。

## 5. 汇总问题，再发布一次

局部阶段把发现的问题按 cue、问题、修复、已复核证据汇总，完成相关修复后再组装高清版本。最终仍做一次针对交付文件的完整解码、源音频哈希/波形与关键编码帧复查。若这时发现新问题，允许必要修订；不要为“只渲染一次”保留已知缺陷。

项目正文/字段尽量以 `project.json` 与实际声音为来源，生成旁白、字幕、章节等派生文件。审片报告标明对应输出/版本，复制旧项目时不沿用它的成功标记；打包前校对报告与实际交付文件一致。封面和文案可单独更新，不重新合成视频或覆盖已经交付的包。
