## 实际材料与复现

- 成片已发布到抖音，本地视频与配音WAV在0.3.0删除；仓库只保留源码、分镜与PNG基准帧，可做静音预演与视觉校准，不能再出有声成片。

历史工程的`animatic`模式逐镜显示完成态，适合布局/镜头顺序粗看；不能据此宣称先后关系已检查。时序复核用`pilot`或`preview.py`的实际时间动态，制作新片的animatic按必要关键状态推进。

Git不分发WAV/视频、个人录音、profile、raw、模型或缓存；缺配音仍能校准、出静帧和静音动态预演。字体默认苹方SC/系统黑体，可用`EXPLAINER_FONT`指定合法字体；环境/字体变化会改变像素，不自动视为校准通过。

## 这次为什么反复对齐表达

| 反复出现的断点 | 没解决前提的修法 | V20采用的表达与可迁移做法 |
|---|---|---|
| 开头不知道DeepInfer解决什么 | 先罗列优化名字、开源意义或厂商影响 | 从公司请假客服请求进入设备、读参数、计算、回答、排队，建立执行问题，再出现引擎。先让任务与开销可见 |
| “算得更多，耗时未必同比增加”像反逻辑 | 用设备/批次的限定句遮住比较对象 | 固定同一设备、同样3个已知位置，比较分3轮和1批，演出重复读取与可共用部分；再说实际时长须测量 |
| 已有vLLM为什么还看DeepInfer | 反复强调“不是模型、不能训练、未必更快” | 先演具体执行选择与收益/代价，再讲官方实现的组合、调度、可研究/复现价值；共享方法和框架对测分别核实 |
| 还不清楚模型为什么多步加工，就直接画层×位置网格 | 加层号、延长保持，或用三个数取平均 | 继续同一请假申请：人物/日期/时长→完整事项→联系教学制度。先展示信息加工的用途，再映射到模型多层共同完成 |
| “第三层为什么依赖第二层” | 只画向上的金色箭头或说“它需要上层结果” | 同一句最后的“一天、找谁、审批”状态带有教学注释，先进入下一层加工，再出现新状态；之后才逆向查所需范围 |
| 请假案例突然切到苹果 | 换一个新例子解释同一缺口 | 保持输入、角色和制度，抽象化也延续同一句；新例子只有增加必要理解时才显式引入 |
| “少算→近似→质量检查”断开 | 最后摆速度/质量两张结论卡 | 片段外的局部读取退出，片段内状态与共享通路保留，输出改标近似并进入生成；同一请假任务比较准备时间和答复质量 |
| 无杂音后觉得赶；放慢后又觉得段落卡 | 同时改语速和段间保持，整片反复加/减速 | 对照原take/处理/母带/AAC，区分瞬态和空白，保留已选PCM，分别调整语速、动作与自然换气 |

## 如何迁移，不把示意当真实内部解释

信息加工三阶段说明“后续利用前面提炼的信息”的用途，并非真实第1/2/3层各负责一个固定语义任务。真实层可同时处理多类特征；旁边的中文是含义注释，不是读取了模型内部文字。规则“一天以内交直属主管审批”为教学假设，未实际执行模型或验证输出。

网格3层、10个文字片段、三位置邻域、起点9与2/4/6范围均为教学简化，不是真实分词、模型层数或窗口数。绿色是正向输入/结果传递，黄色是反向追所需状态。共享状态为另一路输入，局部近似时仍保留；不把普通KV、跨层共享和跨请求前缀命中混为一种缓存。

依赖、局部读取与消费者先有可追踪操作，才接取舍结论。对别的主题可以换成请求字段、索引项、协议状态等受众熟悉对象；不要求所有视频都用请假、三阶段、三层、黄色箭头或成本结论。数学需要型主题保留适当公式，不能因本次数字例子不合适而一律去掉数学。

## 配音与认可范围

V20相对V19保留27段选中WAV，更新5段；保持已选声音与原CTA：“如果这段动画让你有所收获，欢迎点赞收藏加关注，谢谢大家。”邀请开始再退出技术图，不强加分享。

公开`reference-narration-not-distributed`仅为脱敏标记，不能用于合成。新题目配置当前声音、重新录制和重测词时点；保留原录音与处理溯源。0.35秒普通保持、1.25/1.38倍处理、-14LUFS等属于案例结果，不覆盖通用预设或本机profile。已选读法在改稿后继续套用于新正文，正文/字幕仍用规范拼写。

- 更早放缓后的10秒上下文：用户反馈“自然舒服，杂音没有了”，只支持那个声音片段。
- V19约68秒依赖样段：用户反馈“不清楚，这个依赖是啥啊？你倒是举个例子啊”，未通过理解。
- V20约40秒两镜摘录：用户反馈“这次能理解了”，仅支持所示信息加工与层间依赖桥接。
- 原V20整片技术检查：32段源哈希、完整解码/波形对齐通过，最小相关系数0.999983；这些不证明全片人工听感或理解。原MP4 SHA256为`ed4a89e11d46875ad58caa10c959b5a467a8a7e5538884a6a5009cd3992a0bd7`。

技术事实固定于DeepInfer提交`553741557a57df44a46fb3ab72b6aafeaf945337`及相应一手资料。vLLM也有同类方法，没有部署/硬件对测；5.4%只属于官方一组验证策略估算，不是框架胜负或训练成本结论。新选题重新核实事实与支持范围。
