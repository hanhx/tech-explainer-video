# Wi-Fi 主线 V6：导演阐述与逐镜分镜

观众：看过上一集、认识浏览器与路由器，但还不能把协议和现场动作对上。
一句话目标：跟同一台笔记本从 Wi-Fi 接入到网页出现，再解释断开与恢复中每个协议负责什么。
打掉误解：无线网卡不是实体硬件、连 Wi-Fi 就能上网、DHCP 只给 IP、ARP 查询网站 MAC、RARP 是 DHCP 后一步、每次重连必换 IP。
理解曲线：熟悉的选择 Wi-Fi → 连接后 IP 仍空 → DORA 报文填入状态 → 为网站逐步解决邻居与名字 → 放大同一数据 → 断网反例 → 历史对照。
高潮镜头：同一台电脑下面的 IP 一直空白；只有 DHCP ACK 真正到达后，字段才得到值。随后关闭 Wi-Fi，网页和地址字段仍在，新请求却停在接口。

## 引擎与表现方式

沿用浅色手绘。使用 Pillow 过程动画、真实连续相机取景和 FFmpeg 合成：最难的镜头是同一无线网卡推近/拉回、报文沿 AP/网关分支往返、状态字段在到达后更新。它们需要对象与坐标连续，不能由独立卡片淡入替代。手绘纹理固定，避免随机抖动抢焦点。字幕/状态层固定，设备世界可缩放。

不是每镜换一个知识页面：PC-A、无线 B、AP、网关和地址字段在世界中保留；移动报文产生状态变化。DNS 解析器和网站服务器是两个不同对象；进入五层剖面时明确为同一 Q1 的局部回放，进入 RARP 时明确为历史上的另一台设备。无线地址剖面为解密后的概念示意。

## V6 节奏与声音约束

全片 26 镜，实际时长约 7 分 27 秒。增加的时长来自补齐口播和拆分信息，不把旧音频全局减速。14 段沿用原始 WAV，1 段截取已选原声前 4.12 秒，11 段用同一音色新生成。先给实际音频 animatic，再用实际音频动态预演检查关键镜头。

TCP 首次讲解说出“TCP，传输控制协议”；UDP、DNS、ARP、RARP 同样将缩写与中文名绑定。指认用淡色区域、字段填值和接收后的状态变化。动画箭头零调用，移动只用于实际消息或可解释的流程动作。MAC 推近与拉回各 2.1 秒，消息移动通常至少 2 秒；定义读图允许静止，避免为动而动。
