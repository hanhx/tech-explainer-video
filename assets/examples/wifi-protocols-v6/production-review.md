# V6 全片复查与交付记录

## 内容

全片 26 镜；同一台 PC-A 从无有效租约的 Wi-Fi 接入开始，经 DHCP、ARP、DNS 到 HTTPS；关闭并恢复当前接口。五层与传输对比是已发生 DNS Q1 的局部回看，参数和网页保持。RARP 明确切换到另一台历史工作站 C，不加入现代 DHCP 顺序。

配置齐全仍缺网站 IP；本例 DNS 解析器在远端网段，所以要先选网关，并在邻居缓存未命中时用 ARP 找网关 MAC。这层前因已放进口播和画面。UDP/TCP 为并列传输选择；HTTPS 镜头概括 TCP、TLS、HTTP 顺序，完整握手沿用上一集。

## 画面与节奏

- DHCP 的 Request/ACK、四步回放、UDP 端口拆为三镜；回放报文移动分别约 2.98、2.58、2.28、2.00 秒。
- MAC 相机推近和下一镜拉回均为 2.1 秒，动作结束才开始细节解释和新的报文移动。
- 去掉说明性动态箭头。唯一方向变化来自消息位移、字段出现、接收后的状态更新；定义与参数允许读图停留。
- ACK 抵达后才标记配置有效；网页内容抵达后才开始绘制；关闭开关完成后链路失效；历史设备的 RARP 回复到达后才填入 IP。
- 用户指出 MAC 标签和地址挤在同一行，以及共用笔记本紫色线路越框、LAN/WAN 缺边距；MAC 改两行，线路移除，标签内缩。新增父容器与卡片文字相交检查，补充原来只查画布边界的不足。
- 逐镜查看完整低清动态预演的编码首/中/尾采样，并另生成带真实声音的重点动态预演。发现配置卡片压住 Wi-Fi 文字、帧剖面截出半个后方服务器，已修正；断网说明去掉后方无线弧线，避免压字。
- 观察时间来自真实音频、动作预算和独立停留；全片约 7 分 27 秒。没有新增全片语速减慢处理。

## 声音

TCP、UDP、DNS、ARP、RARP 在口播与画面对应常用缩写及中文名。用户在动态预演中指出 ARP 段的声音异常，并指出逐字母 MAC 有卡顿；这段改为自然连读“MAC 地址”，只修复该段，不把整片换声。14 段 WAV 保持 V5 字节不变；Request/ACK 仅截取旧配音首 4.12 秒，PCM 与原文件前缀完全一致；11 段沿用已选音色新合成，保留原始生成音频并记录处理哈希。

已提供可点击的 TCP/HTTPS 与 UDP/TCP WAV，以及带实际音频的动态预演。独立 Whisper base 转写在 TCP/UDP/RARP 段识别出缩写与中文名，但也有其他识别错误，只作为完整性筛查。ARP 的字母拆读方案已因用户指出卡顿而弃用，最终采用自然连读“MAC 地址”的新文件，仅该段应用 afftdn-hiss-v1；新口播没有标记为用户主观听音通过；哈希、ASR 和波形匹配不代表发音和连续听感验收。
