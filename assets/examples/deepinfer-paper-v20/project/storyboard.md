# V20 导演分镜

目标：先看懂同一份请假信息怎样被逐步提炼和组合，再理解后层利用前层中间信息的用途；随后解释近期状态准备、上游范围和局部近似的取舍。

沿用亮色纸张、16:9、手机字号、三项滑动导航。Pillow+FFmpeg固定机位与对象高亮，镜头切换有明确放大对象；不以数学公式替代语义前提。高潮是申请中1天与制度≤1天相连，接着放大同一句最后三个位置的信息如何进入后续加工。

## 观看设计

| 段落 | 引入、操作与兑现 |
|---|---|
| 服务→生成 | 请假问题进入公司助手，已有模型仍需执行；候选验证与调度解释机器做哪些工作。 |
| 输入→层用途 | 同一请求回到输入；人物日期时长→完整事项→联系公司制度。 |
| 层用途→依赖 | 同一句输入排成网格；一天位置更新；最后三份已加工状态进入后层，新状态随后出现。 |
| 依赖→少做工作 | 逆向追所需范围；截定局部读取，保留共享状态，得到近似状态。 |
| 取舍→实际价值 | 对同一请假任务比较时间和答复质量，再回开源、部署、训练中的生成环节。 |
| 结尾 | 回扣可检查和复现的执行方案；保留用户原句CTA。 |

## 简化边界

- 规则“一天以内交直属主管审批”为教学假设，不代表真实企业制度或真实模型执行结果。
- 提取线索、组合事项、联系制度是用于解释用途的信息加工阶段。真实层可能同时处理多类特征，未把三个阶段逐一指定给三个模型层。
- 状态旁的中文是信息含义的教学注释；层间实际传递数值表示，不是模型内部储存的自然语言句子。
- 10个文字片段代指词元位置，不是真实分词。3层、三位置局部窗口、起点9和2/4/6范围均为教学示意。
- 绿色表示实际输入/结果传递，黄色逆向查所需状态。共享状态为额外输入，局部截定仍保留完整输入形成的共享状态。
- 没有DeepInfer/vLLM对测或自有硬件跑分；官方5.4%只属于指定配置的验证策略比较。
- V19的68秒依赖样段得到“不清楚”的反馈，不能列为理解通过；用户反馈40秒两镜摘录“这次能理解了”；这不覆盖其余连续衔接、有界重放/质量段或整片听感。
